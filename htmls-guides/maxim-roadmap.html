What We Just Shipped

The most recent wave focused on Multi-LLM Scaling—giving Maxim the ability to distribute inference across multiple machines with a leader/peer architecture.

LeaderProxy

Authentication, GPU metrics exposure, and debug endpoints. The leader acts as the coordination point for all peer inference requests.

Admission Control

Concurrency caps and rate limiting at the leader level. Prevents overloading any single node when multiple peers submit inference requests simultaneously.

LaneMetrics

Per-lane performance counters for the WorkerPool's three lanes (infer, review, record). Enables monitoring throughput and latency per workload type.

System Heartbeat

Stall detection across the inference pipeline. Automatically identifies when a lane or peer stops responding and triggers recovery.

Peer-to-Leader Inference

Fixed provider priority ordering and pricing gate bugs that prevented peers from correctly routing inference to the leader node.

Process Followup Fix

Eliminated a 60-second stall in the process followup path. Recovery is now instant, preventing cascading delays across the inference pipeline.

Next Up

Prioritized by impact on daily development velocity. Items higher on the list unblock more downstream work.

1

Fix Sim Orchestrator

The simulation orchestrator has issues blocking daily use. This is the highest priority because sims are the primary development and testing workflow.

2

Remote Self-Update (Phase 7a-ext)

Allow Maxim instances to pull updates remotely without manual SSH. Critical for faster iteration when running on headless machines.

3

Simulation Test Bed

Automated regression suite for the sim orchestrator. Provides a safety net so changes to the agent pipeline don't silently break simulation behavior.

4

Phase 7c: mDNS Peer Discovery

Zero-configuration peer discovery on the local network using mDNS/DNS-SD. Eliminates manual IP entry when adding new Maxim nodes.

5

Phase 7d: InferenceRouter

Intelligent routing with local → peer → remote fallback. The router picks the best available backend based on latency, cost, and model availability.

Research Directions

These are speculative, long-term directions. None are scheduled—they represent where the architecture could go once the current engineering work stabilizes.

ATL Self-Extension through Mechanism Discovery

Can Maxim's Anterior Temporal Lobe discover new concept categories and relationship types on its own? Today the taxonomy is hand-coded. A self-extending ATL would let the semantic memory grow in ways its designers didn't anticipate.

Federated Embodiments

Multiple Maxim instances sharing memory and causal models across different physical bodies. A robot that learns to open a door could transfer that knowledge to a different robot with different actuators—adapting the motor plan while keeping the causal structure.

Cross-Agent Affordance Delegation

When one agent discovers an affordance it can't act on (e.g., "this door has a handle but I have no gripper"), it could delegate to an agent that can. This requires a shared affordance vocabulary and a trust model for delegation.

Distributed Embodiment Construction

Multiple agents collaboratively assembling a physical structure, each contributing sensors and actuators. The Agent Mesh provides the communication substrate; this research explores what shared representations are needed for coordinated physical action.

Uncertainty-as-Pain

Mapping epistemic uncertainty to the PainDetector system. High uncertainty about a prediction would register as discomfort, motivating the agent to gather more information before acting—a bio-inspired approach to active learning and cautious exploration.

Dependency Graph

Not everything can run in parallel. This graph shows what blocks what—read arrows as "must finish before."

Dependencies Phase 8 (done) ──> Phase 7b (done) ──> Phase 7d (InferenceRouter) ↑ Phase 7c (mDNS Discovery) ────────────────────────┘ Research Protocol ──> Agent Mesh ↑ Multi-LLM 7c/7d ─────────┘ Embodiment Core ──> Embodiment Hardware Adapter (independent track, no blockers) Simulation Test Bed (independent, unblocks safer iteration) DM MVP (blocked on everything above)

The InferenceRouter (7d) is the key bottleneck: it needs both mDNS discovery (7c) and the Phase 7b/8 infrastructure. Once 7d lands, the Agent Mesh becomes unblocked on its networking side. The Research Protocol unblocks the mesh on its protocol side. Both must converge before mesh work can begin.

Embodiment runs on an independent track. It doesn't depend on the multi-LLM or mesh work, so it can progress whenever engineering bandwidth is available.

Contributing

Maxim is open source. Contributions are welcome—especially on items marked Not Started in the status table above.

Getting Started

  1. Clone the repo from github.com/dennys246/maxim
  2. Read CLAUDE.md in the project root—it covers architectural invariants, testing commands, and the module map
  3. Run maxim doctor to verify your environment
  4. Run the test suite: python -m pytest tests/ -x -q --ignore=tests/integration/test_memory_hub.py
  5. Pick an initiative from the status table and open an issue or PR

Before You Start

The project has strong architectural invariants (one-way memory tiers, separate EpisodicMemory instances, LLM access only through the router). Read the CLAUDE.md section on invariants before making structural changes. The bio-system class names (Hippocampus, ATL, NAc, SCN, EC, AngularGyrus) are intentional and should not be renamed.
