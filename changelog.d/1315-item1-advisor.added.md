- **`maxim.advisor`, the observer** (#1315 item 1; Experimental): `advisor.open(home_dir=, model=, report_dir=, ...)` builds a Maxim that judges a batch of events and proposes, and cannot act. One `session.ingest(events)` is one bounded turn: every event reaches the model framed as untrusted data, with any special token escaped. The completion is grammar-constrained, and every call the model names goes through a sealed executor whose only tool, `propose_action`, records a proposal. Anything else is refused and recorded in the report and the fsynced log. `open()` refuses a code-loading environment, a model that is not a regular file, and overlapping or symlinked directories; it engages the offline latch and reads no Maxim config or data home. See `docs/user/advisor.md`.
- **`maxim.models.language.closed_local`**: the observer's closed llama.cpp backend, built from a GGUF path alone (no profile, router, cost tracker or environment), with a pure-Python GGUF header read that caps the default context at 8192.
- **`maxim.utils.atomic_io.atomic_write_json_at(dir_fd, name, payload)`**: an atomic, strictly fsynced JSON write through a directory fd.
