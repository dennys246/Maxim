# LLM routing & topology — working brief

> Part of the CLAUDE.md satellite layer. Read this whole file before editing `src/maxim/models/language/`, `runtime/lane_*.py`, `runtime/function_router.py`, `runtime/leader_proxy.py`, `runtime/llm_server.py`, `runtime/llm_call_registry.py`, `runtime/stall_threshold.py`, `peer/`, `mesh/`, `tunnel/`, `doctor/`, or `utils/http.py`. The slim CLAUDE.md core + this brief are intended to be sufficient context for work in this area. Full incident narratives: docs/lessons/.

## 1. Mental model

**The dispatch chain.** A function needing inference asks `runtime/function_router.py::FunctionRouter` for a **capability tier** (`large`/`medium`/`small` — what the *work* needs; canonical names, frozen in `runtime/config_loader.py::_VALID_TIER_NAMES`). The tier's `LaneConfig` carries a second, orthogonal **placement axis** (`Origin{LOCAL,CLOUD,PEER}` — *where* it runs), which compiles into `LLMRouter`'s `provider_priority` list. At call time `LLMRouter._try_provider` walks that list, catching typed `BackendError` subclasses specific-before-general and failing over between providers — **failover lives in the router, never inside a backend**. The backend is either `_MaximPeerBackend` (self-hosted peer traffic: exactly one HTTP call, typed failure, strict mid-stream fail) or `_OpenAIBackend` (cloud: internal retry tolerance, lenient streaming). Backend class selection is one dispatch table: `runtime/lane_backends.py::BACKEND_CLASSES` + `resolve_backend_class`. Self-hosted requests then pass through the **LeaderProxy** (`runtime/leader_proxy.py` — context-overflow admission gate, TTFT keepalive, concurrency/rate admission) to llama-cpp-server (auto-spawned by `lane_backends`, singleton-guarded by `runtime/llm_server.py::check_existing_llm_server`), possibly via a cloudflared tunnel. 8 cloud providers; the profile roster lives in `models/language/config.py::_BUILTIN_PROFILES` (don't trust counts in prose — read the dict).

**The topology half.** Every process has exactly one **role** — leader / peer / solo — detected once at startup and read from `os.environ["MAXIM_ROLE"]` thereafter (detection order and single-source rule: docs/agents/persistence-config.md). Mesh topology is **declarative** (`mesh.yml`, operator-edited, runtime-read-only, frozen hand-rolled parser); all mutable peer/mesh state (drain, rate limits, traces) lives in `~/.maxim/util/{name}.{role}.*`. `maxim doctor` and `maxim tunnel` are the operator-facing diagnostics for this whole surface; probes always go through `_MaximPeerBackend.for_url(...).health_check()` and classify through `peer/probe_classify.py` — one probe entry point, one classifier.

**Which timeout fires first** (outermost last):

| Layer | Value | Behaviour |
|---|---|---|
| Proxy admission gate | pre-dispatch | Rejects oversize prompts with HTTP 413 *before* any timer starts (estimated prompt + max_tokens + overhead > n_ctx) |
| Proxy TTFT keepalive | 30s cadence (`MAXIM_PROXY_KEEPALIVE_INTERVAL_S`, clamp 5–90) | Emits SSE comment frames so cloudflared's ~100s idle timeout doesn't kill the stream while a big model computes its first token |
| HTTP-layer per-tier timeout | `lanes.<tier>.timeout_s`; backend defaults 300s peer / 60s cloud | Fires FIRST on a hung call → typed `BackendTimeout` → clean lock release + router failover |
| Router cooldowns | auth 300s, model_missing 60s, `INFERENCE_BROKEN_BACKOFF_S` 15s | Per-provider backoff between failover attempts (router layer, never backend) |
| Agent-level call timeout | `MAXIM_LLM_CALL_TIMEOUT_S` 300s (clamp 10–1800) | Strictly larger than the HTTP layer so it never fires first; if it fires, the HTTP layer is wedged — a LOUD bug signal |
| Stall detection | `runtime/stall_threshold.py::compute_stall_threshold` | Not a timeout — suppresses spurious nudges by consulting `llm_call_registry` for in-flight calls |

Probe timers are separate and short: `MAXIM_REMOTE_PROBE_FIRST_TIMEOUT_S` 1.5s / `..._RETRY_TIMEOUT_S` 8s / cache TTL 60s.

## 3. Invariants & lessons

### Router & backends

**[engineering] `_MaximPeerBackend.complete_with_usage()` makes EXACTLY one HTTP call.** Adding a `try: ... except: <call again>` block anywhere in `maxim_peer_backend.py` re-introduces the ~52s fail-slow incident — failover is the router's job (`_try_provider` catches typed `BackendError`s specific-before-general). Per-provider cooldown goes through `LLMRouter._note_provider_overload`/`_set_long_backoff`/`_set_short_backoff`, never inside the backend; long-cooldown branches deliberately skip `_note_provider_failure` — do NOT add it for symmetry. Full history: [docs/lessons/peer-backend-one-http-call.md](docs/lessons/peer-backend-one-http-call.md). Regression guard: CI grep `grep -nE "retry|backoff|gateway" src/maxim/models/language/maxim_peer_backend.py | grep -vE "retry_after_s|retry_timeout_s"` must return zero matches; enforced in [.github/workflows/test.yml](.github/workflows/test.yml).

**[engineering] Streaming contract difference between `_MaximPeerBackend` and `_OpenAIBackend` is intentional.** Cloud silently collects partial output mid-stream; peer raises `BackendDown` on ANY mid-stream failure so the router can fail over. Do NOT "fix" the peer backend to match the cloud one — that re-introduces the silent-partial-output bug class Plan 3 eliminated. Full history: [docs/lessons/peer-vs-cloud-streaming-contract.md](docs/lessons/peer-vs-cloud-streaming-contract.md). Regression guards: `test_streaming_mid_stream_malformed_chunk_raises_backend_down` + `test_streaming_connection_error_mid_stream_raises_backend_down` + `test_streaming_empty_content_raises_backend_down`.

**[engineering] Any liveness/readiness probe against a peer URL MUST use `_MaximPeerBackend.for_url(url, api_key=k, model=m).health_check(enable_stage2=...)`** — never the removed shims `probe_llm_server` / `llm_server_responding_at` / `_probe_once`. `for_url` is concurrency-safe via instance-level `_api_key_override` and does NOT mutate `os.environ`; new backend factories use the same instance-attribute pattern — do NOT mutate process-global state from a factory call. Full history: [docs/lessons/probe-entry-point-health-check.md](docs/lessons/probe-entry-point-health-check.md). Regression guard: zero-match CI grep in [.github/workflows/test.yml](.github/workflows/test.yml) ("deprecated probe shims" block) — any `probe_llm_server` / `llm_server_responding_at` reference in `src/maxim/` fails CI. Regression guard: [src/maxim/models/language/maxim_peer_backend.py::_MaximPeerBackend.for_url](src/maxim/models/language/maxim_peer_backend.py) — `_api_key_override` is an instance attribute, not a module-level variable; pre-merge review caught the env-var race and pinned the fix.

**[engineering] HTTP errors are typed, not string-matched.** Callers branch on `HTTPError`/`BackendError` subclasses (`.status`/`.fix_hint`), never parse messages; do NOT introduce a parallel exception type — extend the hierarchy in `types.py` + add the matching `_try_provider` router branch in **specific-before-general order** (order violation = the R2c auth-misclassified-as-inference_broken bug class; this brief is the canonical home of that ordering rule). `INFERENCE_BROKEN_BACKOFF_S = 15.0` is the single source of truth linking router backoff to probe cache TTL — import, don't duplicate. Full history: [docs/lessons/typed-http-errors.md](docs/lessons/typed-http-errors.md). Regression guard: [src/maxim/utils/http.py](src/maxim/utils/http.py) + [src/maxim/models/language/types.py](src/maxim/models/language/types.py) (typed hierarchies) + `LLMRouter._try_provider` specific-before-general catch order in [src/maxim/models/language/router.py](src/maxim/models/language/router.py).

**[engineering] `BackendError.fix_hint` is never user-controllable.** Format strings are always static (validated identifiers may be interpolated); access patterns are exactly three: `.status`, `.response`, `.fix_hint` — do NOT add `raw_body` or any parallel attribute (the router bridge counts on the shape matching `HTTPError`). Import `INFERENCE_BROKEN_BACKOFF_S`, don't duplicate it. Full history: [docs/lessons/backend-error-fix-hint-static.md](docs/lessons/backend-error-fix-hint-static.md). Regression guard: [src/maxim/models/language/types.py](src/maxim/models/language/types.py) — `BackendError` hierarchy with class-level `fix_hint` strings (static format strings, not user-controllable).

**[engineering] Lane = capability tier (`large`/`medium`/`small`); placement/origin (`LOCAL`/`CLOUD`/`PEER`) is a SEPARATE ordered axis.** Placement rides on `LLMRouter`'s existing `provider_priority`/`_try_provider` failover — NOT a new resolver (a second resolver re-introduces the multi-call hazard the one-HTTP-call invariant kills). Empty `placement == ()` derives from legacy fields byte-identically; non-empty placement is authoritative (CLI edits on top); multi-element placements compile via tail-injection; `MAXIM_MAX_CLOUD_LANES` keys off `placement[0].origin` only; coherence is enforced at the producer boundary, not in `ProviderPlacement.__post_init__`. Full history: [docs/lessons/lane-capability-placement-split.md](docs/lessons/lane-capability-placement-split.md). Regression guard: [tests/unit/test_lane_placement.py](tests/unit/test_lane_placement.py) (`_legacy_classify_oracle` equivalence matrix + explicit-placement dispatch) + [tests/unit/test_lane_placement_config.py](tests/unit/test_lane_placement_config.py) (schema + coherence-at-load) + [tests/unit/test_lane_placement_runtime.py](tests/unit/test_lane_placement_runtime.py) (producer + tail-injection + CLI re-expression).

**[engineering] Per-tier `lanes.<tier>.timeout_s` flows through `LaneConfig.remote_timeout_s` → `providers[key]["timeout_s"]` with no backend wiring changes.** Do NOT change either backend's default timeout to honor a missing config: 300s self-hosted / 60s cloud is the right pair, and config absence means "use the backend default" — not "use 0". Loader raises on invalid values; `apply_lane_env_overrides` silent-ignores as belt-and-suspenders. Full history: [docs/lessons/lane-timeout-flow.md](docs/lessons/lane-timeout-flow.md). Regression guard: [tests/unit/test_config_loader.py::TestLaneTierTimeoutField](tests/unit/test_config_loader.py) + [tests/unit/test_leader_proxy.py::TestLaneTimeoutFieldFlow](tests/unit/test_leader_proxy.py) (env passthrough into LaneConfig.remote_timeout_s).

**[engineering] Peer transports are typed per purpose, not generic — do NOT extend `_MaximPeerBackend` to carry non-LLM payloads.** `_MaximPeerBackend` is the LLM-inference transport; its "exactly one HTTP call, no retry, typed `BackendError`" rule was earned via the 2026-04-12 fail-slow incident. Future peer transports (perception in 1.1 per [docs/plans/deferred/mesh_perception_transport.md](docs/plans/deferred/mesh_perception_transport.md), substrate bundle in 1.1+ per [docs/plans/maxim_hivemind.md](docs/plans/maxim_hivemind.md)) each live in their own file **next to their domain** (LLM at `models/language/`, substrate-bundle next to `hivemind/bundle.py`, perception next to the percept surface) — do NOT force a `models/<modality>/` convention that fights the module layout. What every transport shares is the playbook: single-purpose backend, typed exception hierarchy with `.fix_hint`, no internal retry, `for_url(api_key=k)` factory with instance-level override (no `os.environ` mutation), `health_check()` as the probe entry point. Stretching one transport across purposes makes the load-bearing one-call invariant ambiguous — router-handles-retry is LLM-specific; a dropped perception frame is a missed observation the agent loop tolerates, not a failover event. Full history: [docs/lessons/typed-peer-transports.md](docs/lessons/typed-peer-transports.md). Regression guard: the existing CI grep on `maxim_peer_backend.py` (enforcing the one-HTTP-call rule via `grep -nE "retry|backoff|gateway"`) is the template the next transport copies; any new transport class adds its own CI grep allow-list entry on the same pattern so cross-transport leakage stays out.

**[engineering] `Percept.to_wire_dict/from_wire_dict` (cross-process transport) and `to_dict/from_dict` (leader session persistence) are separate contracts, versioned independently under `_format_version`.** `embedding` and `substrate_node_id` are NEVER on the wire — the leader owns the substrate; the peer ships raw observations (leader-derived `salience`/`novelty` + `maxim_runtime` also excluded). Network-backed `PerceptSource`s are non-blocking-by-design: `next_percept()` MUST NOT make a synchronous network call; a blocking variant requires a parallel Protocol. Full history: [docs/lessons/percept-wire-format.md](docs/lessons/percept-wire-format.md). Regression guard: [tests/unit/test_percept_wire_format.py](tests/unit/test_percept_wire_format.py) pins the wire-dict whitelist + the substrate-fields-never-on-wire invariant + the explicit wire/session divergence + [tests/unit/test_percept_source_protocol.py](tests/unit/test_percept_source_protocol.py) pins `isinstance(stub_RemotePerceptSource, PerceptSource)` so a Protocol-shape change that breaks the 1.1 adapter fails here. (Also see docs/agents/runtime-tools.md for the `Percept` type itself.)

**[engineering] Any code that enters an httpx stream context manager manually via `.__enter__()` MUST store a reference to the context manager that lives at least as long as the consumer reading the stream** — GC calls `__exit__()` (closing the stream) the moment the ctx goes out of scope. The `_stream_ctx` field in `StreamingResponse` is load-bearing — do not set it to `None` or remove it. Full history: [docs/lessons/httpx-stream-ctx-lifetime.md](docs/lessons/httpx-stream-ctx-lifetime.md). Regression guard: [src/maxim/utils/http.py](src/maxim/utils/http.py) — `StreamingResponse._stream_ctx` field declaration + `close()` enters the context manager's `__exit__`; structural enforcement via the dataclass shape.

**[engineering] `RequestContext` + `contextvars.ContextVar` is the multi-agent contract.** Set at the request boundary (agent loop, sim orchestrator), read automatically by `maxim/utils/http.py::_build_headers` to populate `X-Maxim-*` outbound headers on internal endpoints. Callers don't thread the context through function signatures — set the contextvar, read at the leaves. The `HTTPEndpoint.internal: bool` flag gates which endpoints propagate X-Maxim-* — third-party URLs (HuggingFace, DuckDuckGo, tool fetches) use `internal=False` so request IDs don't leak. When adding a new cluster-internal endpoint, set `internal=True`; when adding an external one, set `internal=False`. Regression guard: [src/maxim/utils/http.py::_build_headers](src/maxim/utils/http.py) — propagation gated by `HTTPEndpoint.internal` flag at endpoint registration.

The leader's `_probe_upstream_ready()` once silently got 401s from an auth-gated llama-cpp-server, leaving `llm_ready` permanently false. ## 4. `maxim doctor` — maintenance guide

Runs platform-aware checks + prints fix hints with the user's actual IPs filled in. Three modules in [src/maxim/doctor/](../../src/maxim/doctor/): `platform_detect.py` (OS + runtime + distro), `checks.py` (pure check functions returning `CheckResult` with status ok/warn/fail/info), `cli.py` (`maxim doctor` + `maxim peer test`). Flags: `--retry` (interactive fix loop), `--json`, `--as peer <url>` / `--as leader` / `--as solo`. Companion: `maxim tunnel` in [src/maxim/tunnel/](../../src/maxim/tunnel/).

**Adding a new check:**
1. Write a pure function in `doctor/checks.py` taking `PlatformInfo` (if platform-aware), returning a `CheckResult`.
2. Add it to the correct section in `run_all_checks()` — peer-only checks in the `detected_role == "peer"` branch, leader/solo in the `else` branch.
3. If the fix differs per platform, branch on `info.runtime` / `info.os` / `info.distro` and produce platform-specific `fix` strings with copy-pasteable commands.
4. Use actual detected values (`detect_wsl_ip()` / `detect_lan_ip()`), not `<your-ip>` placeholders.
5. Add a unit test in `tests/unit/test_doctor.py`; mock network/process calls so tests run offline.

**Cross-module imports:** import inside the function body (not module-level) so `maxim doctor` stays fast when optional features aren't installed. Tests must patch the **original** module path (`maxim.tunnel.cloudflared.find_cloudflared`), not `maxim.doctor.checks.find_cloudflared`.

**Retry loop** (`--retry`): data-driven — any `CheckResult` with a `retry_id` and non-ok status is included; add the retry_id to `retryable_fns` in `cli._retry_loop`. **Role detection** (`_detect_doctor_role()`): a non-localhost `MAXIM_LANE_LARGE_REMOTE_URL` triggers peer mode; override with `--as`. **New platform:** extend `PlatformInfo`'s Literal types + detection branches + fix-hint branches in every platform-aware check. **`maxim peer test` stays self-contained** — no imports from the agent runtime (peers may lack the full dependency set).

**Don't:** auto-execute fixes without explicit opt-in (`--fix`); make checks slow (>1s — network probes use 1.5–2s timeouts; benchmarks belong elsewhere); silently drop failures — every failing check needs a user-actionable `fix` string.

## 5. Remote update — details

Core keeps the two command lines and the safe/unsafe verb split. Details: `maxim peer update` auto-detects pip-installed vs git-checkout leaders; `--dry-run` first if unsure; `--version X.Y.Z` pins a PyPI version; `--dev [branch]` forces git mode (default `origin/main`); `--force` (dev mode only) when untracked files block the pull; `maxim peer install <extra>` / `maxim peer deps` manage leader extras. Troubleshooting: [docs/troubleshooting/remote_update.md](../troubleshooting/remote_update.md). Version sync check: `maxim peer version` — mismatch means the leader needs `maxim peer update && maxim peer restart`.

## 6. Live gotchas / known gaps

- **Singleton spawn guard + harness preflight** (the code half of the "never run the harness on the leader" lesson — incident home: docs/agents/simulation-experiments.md): `runtime/llm_server.py::check_existing_llm_server` probes the singleton port before any spawn — 200 + matching model → reuse; 401 → reuse; refused → spawn; 200 + DIFFERENT model → `RuntimeError` (fail loud). `lane_decisions.jsonl` sources `"env"`/`"reused_server"` are accepted by the harness preflight; a fresh local spawn (`"tier_table"`) is the cascade signature and is rejected.
- **n_ctx drift, cross-process reuse still OPEN:** auto-spawn stamps `LaneConfig.served_n_ctx` so the worker clamp and `router.n_ctx` track the real served window in-process, but a sub-sim in another process reusing the leader's server sees no stamp → profile-default budgeting → oversize prompt → raw HTTP 500 → silent `_llm_unavailable`. `maxim config set llm.n_ctx` alignment remains mandatory for harness/sub-sim runs. Do NOT re-add `max()` to the worker budget clamp ("restore cloud routing" is the trap). Guards: [tests/unit/test_lane_served_nctx.py](../../tests/unit/test_lane_served_nctx.py), [tests/unit/test_llm_worker_n_ctx_clamp.py](../../tests/unit/test_llm_worker_n_ctx_clamp.py).
- **Stall detector drift:** the orchestrator's `_stall_detector` hardcodes `lane_tier="large"` and reads `MAXIM_LANE_LARGE_TIMEOUT_S` directly (not via `LaneConfig.remote_timeout_s`) — drifts silently if `lanes.large.timeout_s` is set via config.json only. Tracked follow-up.
- **heartbeat.py STALL allowlist** in the CI grep is still "pending Stage 2" — Stage 2 has not shipped; the allowlist entry is current.
- **Canonical tier names** are `large`/`medium`/`small` only; `infer`/`review`/`record` were removed and are CI-grep-blocked. `_VALID_TIER_NAMES` lives in `runtime/config_loader.py`.
- **Deprecated-but-working aliases:** `--cloud-lane`/`--cloud-fallback` (+ `MAXIM_CLOUD_LANE_*`/`MAXIM_CLOUD_FALLBACK_MODEL`) are re-expressed as placement edits; kept through 1.x, drop in 1.2. The env-driven `_maybe_inject_cloud_fallback` runs ONLY for derived lanes (`placement == ()`); explicit placements use tail-injection — exactly one path.
- **Doctor follow-ups** are no longer tracked as inline TODOs (that claim went stale — zero TODO/FIXME matches in `src/maxim/doctor/`).
- **`agents/llm_agent.py`** still imports a backend directly — grandfathered on the router-only CI grep allow-list; migration to the router is tracked follow-up work.
