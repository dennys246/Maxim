## 1. Mental model

**Boot ordering.** All startup logic lives in `cli.py::_main_impl`; `main()` is now a thin error-surfacing wrapper around it. The ordering inside `_main_impl` is load-bearing, in this exact sequence:

1. `configure_logging` — at the very top, BEFORE subcommand dispatch, so `MAXIM_LOG_FILE` and structured events work for the `doctor`/`peer`/`tunnel` short-circuits too (the sim loop's later `configure_logging(force=True)` dedupes handlers, so early+late is safe).
2. `runtime/role.py::detect_and_apply_role(raw_argv)` — role detected ONCE, exported as `MAXIM_ROLE`; downstream reads env, never re-detects (home: docs/agents/persistence-config.md).
3. LeaderProxy start — BEFORE `_normalize_args()`, because arg normalization can trigger heavy CUDA imports (5-15s) and peers polling for the proxy during restart would time out.
4. `_normalize_args()` → subcommand dispatch / sim loop.

Any code that runs early in `_main_impl` and consumes `argv` must explicitly handle subcommand entry paths (`maxim tunnel --llm X` once mis-detected role as `solo`).

**Loop anatomy.** `runtime/agent_loop.py::run_agentic_loop` (with `LoopController` in `runtime/loop_controller.py`) is the per-tick spine: pause check → `tick_embodiment_drift` (LLM-primary only; see docs/agents/embodiment.md) → idle gate → percept intake → prompt composition via `PromptBuilder`/`PromptBudgeter` → LLM dispatch through `LLMWorker` + its owned `WorkerPool` → `Executor` tool dispatch (side_effects routed to bio bridges) → section 8.5 NAc per-tick decay (see docs/agents/bio-memory.md) → imagination hook (see docs/agents/simulation-experiments.md).

**Thread model.** Main loop at 2-30Hz + WorkerPool (tier-based lanes: large/medium/small, owned by LLMWorker at `agents/llm_worker.py`) + Hippocampus capture thread (owned + shut down by `MemoryHub.on_session_end`).

**The canonical-builder family.** Six builders exist because of one governing principle — *push silent-no-op invariants into types, not helpers* (lives in CLAUDE.md core; full history: [docs/lessons/silent-noop-invariants-into-types.md](docs/lessons/silent-noop-invariants-into-types.md)). Each builder converts a "forgot to wire X" bug that used to fail silently (no exception, no log, just missing learning) into a `TypeError` at construction time via required keyword-only parameters. `None` is always the explicit opt-out; `_allow_raw=True` is the test-only escape hatch on the raw constructors. The table in §3 lists what each one used to silently break.

**Python API (pymaxim).** `src/maxim/api.py` exposes verb-based functions (the `_API_VERBS` frozenset in `src/maxim/__init__.py`), all lazy-loaded. Maintenance rules: **verbs are facades, not logic** — delegate to existing internals; **lazy imports only** — `import maxim` must not load optional dependencies; **return structured data, not prints** (`diagnose()` → `DiagnosticReport`, `imagine()` → `SimulationResult`); **`introspect` is an alias for `observe`** — don't add behavior to one without the other; **`Observer` is the canonical name** (no aliases). Package: `pymaxim` on PyPI, import name `maxim`; `pyproject.toml` is the dependency authority and currently declares seven core packages (`numpy`, `scipy`, `pyyaml`, `json-repair`, `httpx`, `rich`, `filelock`), while feature-specific stacks remain optional extras; robot plugins auto-discover via the `maxim.robots` entry-point group; build into a unique artifact directory and run `twine check` before any publish (guide: [docs/publication_guide.md](../publication_guide.md)).

## 3. Invariants & lessons

**[engineering] Canonical builders — six construction sites, one pattern: required keyword-only wiring so forgetting is a `TypeError`, not a silent no-op.** Raw construction of `PainBus()` / `ReactionBus()` / `MemoryHub()` raises `TypeError`; tests pass `_allow_raw=True` explicitly (the structural test-only opt-out). `None` on a required parameter is always an explicit opt-out decision, never a default.

| Builder | Site | Required kw-only | What forgetting used to silently break |
|---|---|---|---|
| `build_executor` | `runtime/bootstrap.py::build_executor` | `pain_bus=` (`None` = opt-out) | Three identical "forgot to wire ToolPainBridge" bugs silently skipped NAc tool-outcome learning on three agent entry points |
| `build_pain_bus` | `proprioception/pain_bus.py::build_pain_bus` | `hippocampus=`, `nac=` | Three CLI entry points subscribed only the memory subscriber — out-of-band SEM pain reached hippocampus but never NAc |
| `build_reaction_bus` | `reactions/bus.py::build_reaction_bus` | none (generic typed pub/sub) | `cerebellum_modulator_factory` silently dropped its `reaction_bus=` param — every SEM modulator failure reaction discarded |
| `build_default_network` | `runtime/bootstrap.py::build_default_network` | `nac=` (`None` = opt-out) | DN constructed its own bus with split subscriber ownership; hippocampus wired externally, easy to miss |
| `build_memory_hub` | `integration/memory_hub.py::build_memory_hub` | `hippocampus=`, `scn=`, `nac=`, `ec=` | Two production sites never called `.connect()` — all three learning bridges permanently `None` |
| `build_bio_stack` | `runtime/bio_stack.py::build_bio_stack` | `agent_id=` (+ composes the other builders in dep order) | A defaulted `agent_id` silently diverged `MemoryHub.agent_id` from every other surface, breaking Wire-A's cross-session annotation read |

Per-builder clauses that must survive:

- **`build_executor`:** bridges cannot be retrofitted onto an Executor — wrapping (`FearGatedExecutor`, `PainInterceptorExecutor`, `AnticipatoryPainExecutor`) MUST happen AFTER `build_executor` returns; the deleted helper `bootstrap_embodiment_and_pain_bridge` must not be re-introduced. Fail-fast invariants check at the top BEFORE any construction: `pain_bus` XOR `pain_detector`; `entity_ref` requires `pain_bus` + `component_registry`; any subscription path requires `nac`. Bridge construction gates on `nac is not None`, NOT on `pain_bus`. Five logical call sites (`api.py`, `runtime/agent_factory.py`, `simulation/tools.py`, `simulation/foundry.py`, `embodied_runtime/agentic_runtime.py`) — six physical calls (agentic_runtime has an if/else pair); CLI + sim orchestrator now route through `AgentFactory.create_full_agent`. The headless `api.py::run` `learning=False` branch keeps its explicit `pain_bus=None` opt-out; the `learning=True` default routes through AgentFactory with the full bio stack.
- **`build_pain_bus`:** auto-subscribes the standard memory + NAc pain learners; takes only learning subjects (no ReactionBus, no enabled flag, no kind filter — gate on the learning subject, not the signal source). **Tripwire: if `test_subscriber_does_not_link_pending_tool_event` fails, DO NOT relax the assertion** — the bridge/subscriber no-double-count property is load-bearing on the context-similarity mismatch, not on any guard; open [docs/plans/deferred/pain_bus_bridge_subscriber_unification.md](docs/plans/deferred/pain_bus_bridge_subscriber_unification.md) and ship the deeper fix (bridge-aware subscriber or inverted wiring), never a `_pending_tools` guard band-aided onto the subscriber.
- **`build_default_network`:** `pain_bus=` injection inverts DN from bus **constructor** to bus **consumer** — the injected bus already carries the hippocampus + NAc subscribers from `build_pain_bus`. Current truth (supersedes the old "Wave 2 deferred" wording): both production callers inject via `build_default_network(pain_bus=…)`; direct `PainBus(_allow_raw=True)` construction at `default_network/network.py::DefaultNetwork` survives only as the no-injection fallback. `maxim=None` is the headless/sim opt-out (DN still provides pain detection + novelty tracking without motor control); `ImportError` → `None` + warning, config/type errors propagate.
- **`build_reaction_bus`:** no required learning-subject params by design; sequencing matters — construct the ReactionBus BEFORE `build_pain_bus(..., reaction_bus=rb)` because PainBus depends on it at construction time.
- **`build_memory_hub`:** **always calls `.connect()` internally**, so the three always-created bridges (PlanHistoryBridge, EscalationLearningBridge, FearCircuitBridge) are alive on every hub the builder returns. A second `.connect()` later is safe (bridges are stateless at construction; overwrite). Carries the same required-`agent_id=` contract as `build_bio_stack`.
- **`build_bio_stack`:** `agent_id=` is REQUIRED keyword-only; `persistence_dir` derives sub-paths internally; `pain_bus=` accepts a pre-built bus (sim AUT pattern) and subscribes standard learners onto it. Two production callers: `AgentFactory.create_full_agent` (fans out to CLI non-sim, sim orchestrator AUT + NPC, headless `pymaxim`) and the Reachy `embodied_runtime/agentic_runtime.py`.

**[engineering] Mutable globals + module extraction:** When extracting module-level mutable globals (like `_active_spawner`) into a new file, do NOT re-import them by name (`from new_module import _active_spawner`). Python binds by value at import time — assignments in the importing module diverge from the source. Use module reference instead: `import new_module as _mod; _mod._active_spawner = value`. Functions are safe to re-import (they close over their own module's namespace). Full history: [docs/lessons/mutable-globals-module-extraction.md](docs/lessons/mutable-globals-module-extraction.md). **[engineering] A planning turn that ends without an executable proposal MUST route through `agent_loop::_handle_planning_failure` — never fall through to idle.** Covered outcomes are fallback/parse failure, error proposal, stale proposal, an unregistered-tool choice, a parsed proposal with neither action nor error, and an exact worker job consumed without publishing a proposal. Adding another drop site without this call re-creates the D13 livelock, because the loop already cleared `pending_action_followup` and deduped the triggering input when the failed request was BUILT — nothing else can re-arm it. Three rules are load-bearing: (1) the machinery is OPT-IN (`run_agentic_loop(planning_liveness=True)`) and only the sim orchestrator opts in; (2) liveness is decided from `LLMWorker.latest_attempt_state()` for that worker's exact `WorkerPool` job, never from the process-global call registry or the legacy 120s window; `PENDING`, `RUNNING`, and `COMPLETED` (queued but not consumed) keep the proposal poll awake; (3) planning failures and worker-transport failures have separate bounded budgets. Unregistered-tool/no-action/stale exhaustion reports `planning_failed`, parse/provider exhaustion reports `llm_wedged`, and worker/queue exhaustion reports `worker_unavailable`; a bad tool is inserted into the retried request's corrective prompt rather than requeued byte-identically. Operator opt-out `MAXIM_SIM_PLANNING_LIVENESS=0`. Full mechanism + evidence: [docs/bugs/README.md](../bugs/README.md) rows D13/D14. Regression guards: [tests/unit/test_planning_liveness.py::TestLoopWiringPins](../../tests/unit/test_planning_liveness.py), [::TestSlowCallIsNotALostTurn](../../tests/unit/test_planning_liveness.py), and [::TestExactJobStateClosesPublicationRace](../../tests/unit/test_planning_liveness.py).

**[engineering] The architecture audit is a regression gate against a REVIEWED baseline, never a permanently-red report.** `utils/audit.py::audit_architecture` tags each cross-layer import with its scope (`module` / `function-local` / `type-checking`) and `compare_to_baseline` diffs the findings against `utils/architecture_baseline.json` (keyed `file::imported_module::scope` + count — never by line; a typing-only edge becoming a runtime edge is a NEW finding by design). Adding a cross-layer import means either fixing it or adding a baseline entry WITH a rationale in the same commit; removing one means shrinking the baseline in the same commit (a stale entry fails too, so the baseline cannot overstate the debt). `UNREVIEWED` entries fail; widening an accepted `from X import a` to `a, b` is a NEW finding (entries carry the accepted symbol set); `from maxim import tools` and relative forms are resolved per name (dynamic `importlib` imports are out of scope by design). Burn-down toward zero is the 1.1.x list's item 11 in the roadmap; the baseline ships in the wheel so `maxim --audit-architecture` reports the same verdict as CI. **[engineering] Console sandbox mode closes the HOST-acting surfaces; it never adds auth, and shutdown persists BEFORE releasing the sink.** `maxim serve` is localhost-only and unauthenticated by design (the operator's machine is its trust boundary). Under `MAXIM_CONSOLE_SANDBOX=1` — read once at `build_app`, never per request — the three surfaces that act on the host rather than on the agent are refused with 403 (`/api/probe` with a `url` = SSRF with an attacker-chosen bearer; `/api/setup/mesh` = persistently repoints the LLM lane; `/api/diagnose` = renders resolved config — key BYTES are redacted by the doctor's `_is_secret_field` path, but paths/env names/IPs are a recon surface), `/ws` upgrades are refused before `accept()` unless the Origin is listed, `RunRequest.input` is capped, and `/api/identity` reports the closed seams `live=False` instead of letting the client discover the 403. Authentication stays OUT of the engine: auth that lived here would have to be trusted by every localhost user, so the proxy in front owns it. Separately, the lifespan's drain-and-stop now runs INSIDE the shutdown `finally`, ahead of the sink release — a Talk-only session writes nothing to disk until the handle stops, and the old ordering let any exception through shutdown skip exactly that step. `_drain_and_stop_handle` is module-level so the contract is testable without uvicorn, and `MaximHandle.stop()` takes both waits (`campaign_wait_s`, `talk_join_s`) so a caller with its own deadline can shorten them. Regression guard: [tests/unit/test_console_sandbox.py](../../tests/unit/test_console_sandbox.py) (`TestClosedSurfaces` with per-surface negative controls, `TestWsOrigin`, `TestInputCap`, `TestShutdown`) + [tests/unit/test_console_handle_stop.py](../../tests/unit/test_console_handle_stop.py).

**[engineering] The console trust guard is ALWAYS on — Host + Origin browser-relay protection, sandbox or not; it is NOT authentication.** Every request and `/ws` upgrade must carry a Host that is loopback or a host of `console.allowed_origins` (DNS-rebinding guard; the `testserver` allowance exists ONLY while pytest runs — `server.py::_test_host_allowance` gates on `PYTEST_CURRENT_TEST`, mirroring Django's test-scoped injection); a state-changing request or `/ws` upgrade that carries a browser Origin must carry a loopback-host origin (any port) or a listed one, and state-changing requests must send `Content-Type: application/json` (CSRF guards — Starlette parses JSON regardless of Content-Type, so this pair is what stands between a page in the operator's browser and `/api/run`/`/api/setup/*`/`/api/probe`). Origin-less clients (CLI, native apps) pass by design. `console.allowed_origins` is the ONE trusted-origins list — it feeds this guard everywhere AND the sandbox `/ws` origin-REQUIRED gate; entries canonicalize LOUDLY at `build_app` (`server.py::_canonical_origin_list` — malformed entry or one whose shape can never match a browser Origin = `ConfigurationError`, never a silent half-applied trust), default ports are dropped on both sides, and listing an origin also whitelists its HOST (the tunnel's public hostname must appear as the host of some listed origin). Resolved once onto `app.state.trust`; a request cannot flip it. Deliberate remote exposure adds real auth on top — ladder: [docs/plans/console_tunnel_hardening.md](../plans/console_tunnel_hardening.md). Regression guard: [tests/unit/test_console_trust_guard.py](../../tests/unit/test_console_trust_guard.py) (every refusal paired with its accepting counterpart; guard-fires-before-config-writers spy; pytest-scoping of the testserver allowance pinned).

## 4. Live gotchas / known gaps

- **`main()` vs `_main_impl`:** all boot-ordering rules bind to `cli.py::_main_impl`; `main()` is a thin error-surfacing wrapper. Older docs and guards that say "top of `main()`" mean `_main_impl`.
- **New opt-in env vars in hot startup paths need autouse conftest scrubs in the same commit** — a test that sets the var leaks the side effect into every later runtime-constructing test (once cost a 9-minute hang on a real 1 GB model download). Template: the existing `_isolate_maxim_*` fixtures in [tests/conftest.py](tests/conftest.py). Full history: [docs/lessons/env-var-autouse-scrubs.md](docs/lessons/env-var-autouse-scrubs.md).
- **Optional dependencies route through `maxim/utils/optional_deps.py`** (`require_optional_dependency` / `optional_dependency_available` / `warn_optional_fallback`) — never a new bare `try: import X except ImportError` in `src/maxim/`. Full history: [docs/lessons/optional-deps-canonical-surface.md](docs/lessons/optional-deps-canonical-surface.md).
- **Agent-loop tick couplings:** section 8.5 NAc decay must stay wired per-tick (docs/agents/bio-memory.md); `tick_embodiment_drift` is a no-op on substrate-primary and unembodied paths — do not add a second `tick_vital_drift(` call site (docs/agents/embodiment.md).
- **`build_pain_bus` latent attribution asymmetry:** the no-double-count property between `ToolPainBridge` and the NAc pain subscriber rests on a context-similarity mismatch, not a guard. Enriching `record_tool_start`'s pending-event context (e.g. adding `entity`) starts double-counting silently — the tripwire test in §3 is the alarm.
- **Headless bio-learning default:** `api.py::run` defaults `learning=True` (full bio stack via AgentFactory); `learning=False` is the explicit `pain_bus=None` opt-out branch. The old "decision belongs to Stage F5" wording is closed — this IS the shipped resolution.
