## 1. Mental model

The substrate is one directed data-flow chain; every invariant below pins one link of it:

```
percept text / sensor reading
  → LinguisticEncoder (similarity/encoder.py; decomposition strategy per surface:
      SpaCyNounChunkStrategy for percepts, AffordanceDecompositionStrategy for affordance names)
  → EC pattern_complete_or_separate (similarity/ec.py: match existing node vs allocate new;
      centroid update UNLESS modality is frozen)
  → ATL semantic graph + Hippocampus episodic tiers (FORMING → SHORT_TERM → LONG_TERM)
  → NAc (decisions/nac.py: reward_bias / cluster_reward_bias keyed on EC node ids,
      causal links keyed on event/outcome signatures, Welford variance on the parent aggregation)
  → SCN temporal credit (decisions/temporal_credit.py::TemporalCreditDistributor —
      the single intake fanning out to NAc eligibility, SCN bins, oscillator phases)
  → back into behavior: prompt annotations (Wire-A cluster-bias, Wire-1 variance band)
      and substrate-primary action selection (agent_loop::propose_via_substrate / NAc.recommend_action).
```

Attribution back into the chain has a strict preference order: **direct lookup key first** (`(tool_name, invocation_id)` → `NAc.record_outcome`), context similarity only as the out-of-band fallback (`record_outcome_full`, directional `_context_similarity`).

**EC threshold table — the numbers people confuse (a real incident: sensor threshold assumed 0.44):**

| Surface | Config field | Default | Notes |
|---|---|---|---|
| Text / linguistic | `ECConfig.pattern_complete_threshold` (similarity/ec.py) | **0.44** | Raised from 0.40 to stop centroid drift (L03); Roy-5 H1C boundary tracks this default |
| Sensor / drive encoding | `SensorEncoderConfig.pattern_threshold` (similarity/encoder.py) | **0.85** | NOT 0.44 — separate config class, separate surface |
| Frozen-centroid modalities | `ECConfig.frozen_centroid_modalities` | `{"interoception", "audio"}` | No running-mean centroid update; must equal hivemind `DEFAULT_FROZEN_CENTROID_MODALITIES` (test-pinned equality) |
| NAc recognition widening | `NAc.get_threshold_overrides(base_threshold=)` | tracks live EC threshold | Callers MUST pass `self.ec.config.pattern_complete_threshold`; the `None` fallback (0.44) is legacy-test-only |

Construction of this whole stack is owned by the builder family (`build_bio_stack` → `build_memory_hub` / `build_pain_bus` / etc.) — also see docs/agents/runtime-tools.md for the builders and the agent-loop call sites; docs/agents/embodiment.md for the pain/credit channels that feed NAc; docs/agents/persistence-config.md for `_format_version`, atomic writes, and stable-hash rules.

## 3. Invariants & lessons

- **[engineering] The object that OPENS a memory session is the object that CLOSES it, and it opens the hub it will still own.** `MemoryHub.on_session_end()` is an atomic test-and-CLEAR that returns `{}` when no session was started, so an owner that never opened one persists only what it saves by hand — `hippocampus.json` + `nac.json` — and silently drops EC, SCN, ATL and the Angular Gyrus; the next load then warns "Half-present NAc/EC pair" on the runtime's own output, manufacturing the orphaned-bias state D2/D17 exist to detect. `AgentInstance.start_session()` owns the open, and `create_full_agent` calls it AFTER swapping in the bio-stack's hub — opening in `create_agent` opened a skeleton that was then discarded, which is the same bug one layer down (both review lenses caught it; reproduced black-box). `on_session_start` is idempotent so the runtime's own `start_bio_session` no-ops on an adopted persistent agent instead of re-running a restore whose `atl.load()` clears before restoring. **Sessions NEST:** the agent loop's `start/end_bio_session` pair sits inside the instance's lifetime and legitimately closes the session the instance opened, so the detector keys on `_session_ever_started` (was one EVER opened on this hub) — keying it on `_session_active` made it fire on every clean runtime shutdown, which is a guard nobody reads. Residual gap, documented not papered over: mutations made after the loop closes and before `shutdown()` are not persisted by that call. Full history: bugs ledger D41/D42 + score card N2. Regression guard: [tests/unit/test_api_core.py](../../tests/unit/test_api_core.py) (`test_create_mutate_shutdown_load_round_trips_ec_scn_atl`, `test_full_agent_construction_opens_the_session_on_the_hub_it_keeps`, `test_the_loop_closing_its_own_session_does_not_make_shutdown_cry_wolf`, `test_a_hub_that_never_opened_a_session_still_warns_on_both_closers`, `test_write_but_dont_read_agents_do_not_restore_scn`, `test_a_corrupt_scn_file_is_preserved_not_overwritten`).

- **[engineering] A memory is ACTIVATED only when it is USED — through `MemoryLayer.activate(ids, source=...)`, never by a read.** Two criteria: LLM paths count at the consumer's RENDER cap, not its retrieval limit (enrichment renders 3 episodes and 5 concepts; the adaptive planner counts in `_decompose`, the only place it renders memories; surfaced-but-unshown is not a use); pattern completion counts at COMPLETION (CA3 reactivation, whether or not anyone reads the prediction), completed episodes only, never the cue concepts. Consumers call it through `memory/layer.py::activate_after_use` AFTER building their content, so a store failure is logged and can never cost them what they received (a bad `source` still raises). **Never call `activate` while holding any lock of that store, or inside `for r in store:`** — `Hippocampus.__iter__` holds the read lock for the whole loop and `RWLock` is writer-priority and NOT re-entrant, so the re-read inside `activate` deadlocks behind a waiting capture worker. Bookkeeping reads (echo filters, session-start bulk recalls, deletion callbacks, neighbour lookups, encoding) stay on `recall_by_ids`. `source` must be in `memory/types.py::ACTIVATION_SOURCES`, checked in `MemoryRecord.activate` itself. `activation_count` is a MASSED, un-deduplicated tally (deliberation re-renders the same top 3 every cycle) — NOT a strength or importance signal: never rank, promote or protect on it (that rebuilds `access_count`'s immortality); Phase 2c-3 hooks `activate` EVENTS instead, through `MemoryStrategy.on_activation`. `touch()`/`access_count` are untouched until the Phase 5 default flip. Every concrete record type serializes the fields through `MemoryRecord._activation_fields`/`_activation_kwargs`, and compression carries them. When hivemind bundles gain an ATL slice, strip `activation_*` — one agent's use is not another's, and the history shows what an agent attends to. Consumers that never deliver today are #845. Regression guard: [tests/unit/test_memory_activation_wiring.py](../../tests/unit/test_memory_activation_wiring.py) (each site against a real store, at its render cap, incl. planner gather-vs-decompose and counting-cannot-cost-content) + [tests/unit/test_memory_activation.py](../../tests/unit/test_memory_activation.py) (discovered-subclass round trip, compression carry, closed vocabulary in the type, lock-free concurrency, and `test_the_strength_strategys_score_moves_with_credited_activations` -- the behavioural gate that REPLACED Phase 1's strict xfail when 2c-3 flipped it).

- **[engineering] Every Hippocampus capture says what it was encoded WITH (`encoding=`, required), and a constant is never recorded as a measurement.** `memory/encoding.py::EncodingSignals` is frozen, with a required closed `site` (`ENCODING_SITES`) and four required `float | None` signals in `[0, 1]` — salience, novelty, surprise, pain; `None` means "not measured here", and `EncodingSignals.unmeasured(site)` is the explicit all-`None` declaration. A value a path stamps on every capture (the 0.5 salience default, pain-bus novelty 0.6, reflexion 0.9/0.8, `store_observation`'s 0.5/0.3) is a constant, recorded as `None`. **`pain` is nociception only** (`proprioception/pain_bus.py::NOCICEPTIVE_PAIN_TYPES`, an innate prior): tool-failure pain is not recorded as pain (its surprise reaches the loop capture), neither is a drive breach the body publishes as external pain (`source="drive:<name>"`, e.g. air hunger → `extra["drive_pain"]`; `drive:health` stays pain, since health loss is tissue damage), and anticipated pain only as `extra["anticipated_pain"]` — never as measured pain. `Hippocampus.capture` is the single choke point (`capture_from_loop`, the async path and `store` route to it); the async path validates on the caller's thread because the worker only logs; a break raises `EncodingContractError`, the one error capture paths do not swallow. The record rides on `EpisodicMemory.encoding` through persistence and compression; a pre-2b trace loads as `None` (not recorded), and a malformed one as `None` with a warning — it never fails the store's load. **Write-only** until the Phase 2c strength strategy reads it. Surprise stays in `[0, 1]` because the Rescorla-Wagner value is bounded at every producer (`decisions/causal_link.py::bound_predicted_value`: `from_dict`, hivemind ingest, merge). **Per drive** (Phase 2b-ii): `drive_pressure` (what the body was pushing for BEFORE the action) and `drive_relief` (how much of each drive's possible relief it gave) are sorted `(drive, value)` tuples, stamped on the invocation's `ToolOutput` by the executor from the record-only `drive_progress_by_drive` side effect; `drive_relief`'s KEYS are Phase 2c's relevance gate (the drives an action actually touched); `drive_pressure` is the WHOLE body's drive vector every capture, so a drive pinned by a scenario (Exp 52's satiated infant, azimuth in a silent sim) records a constant `0.0` there — a measurement of "not pushing", but not evidence the body varies. The normaliser is each drive's own largest possible movement (`embodiment/sem.py::drive_span`): the declared range for a homeostatic drive, and the deprivation-to-satisfaction BAND for an entropic one, never its declared range (those are widened for the encoder's neutral, which put `1.0` out of reach — Phase 2b-ii review). So `1.0` is "the most this drive can give", and pressure and relief share one scale; `drive_comfort_progress`, `_drive_potential_diff` and `corrective_need_intensity` are NOT touched by any of it (credit and perception signals, with their own experiment triggers). Regression guard: [tests/unit/test_memory_drive_signals.py](../../tests/unit/test_memory_drive_signals.py) (span/relief/pressure per drive kind, `sum(per-drive) == credit scalar`, pressure stamped from before the action, a tool cannot stamp its own) + [tests/unit/test_memory_encoding.py](../../tests/unit/test_memory_encoding.py) (required at every door, caller-thread failure, only the contract error escapes, every PainType classified, round trip + compression + legacy + malformed, each live site recording exactly what it measured, the producer bound).
- **[engineering] A loop capture records the SITUATION it happened in, and the situation's concepts link to it** (memory-strength Phase 2S-b, #848). `Hippocampus.capture_from_loop` / `capture_from_loop_async` take a REQUIRED `situation=` — the loop's substrate clusters for the action, `{modality: EC cluster id}`, or `None` when the path computed none (stated at both loop doors; `capture(record=...)` keeps a pre-built record's own situation unless one is passed). A malformed one raises `SituationContractError` — a subclass of the capture-contract `EncodingContractError`, so it escapes the loop capture's DEBUG swallow rather than dropping the trace — on the caller's thread. The value is the clusters the action was CHOSEN in, `ctrl.pending_proposal.clusters` (substrate-primary's proposal, encoded the tick before execution; llm-primary's outcome-time encode before execution) — the key `_rec_outcome` credits, and never a fresh encode at capture, which would key the post-action state and write the EC. Both loop paths go through `agent_loop.py::_loop_capture_action`. The capture's encoding MEASURES pain and novelty there too (Phase 2S-c): pain is `ToolOutput.pain`, stamped by the executor from `ToolPainBridge.pop_invocation_pain` (the NOCICEPTIVE pain this action CAUSED, else the peak NOCICEPTIVE pain FELT while it ran; `0.0` watched-and-none, `None` unwatched — never the dormant `consume_pain_intensity` stash). What counts as pain is decided ONCE, on the type: `PainSignal.kind` / `proprioception/pain.py::classify_pain` (and `failure_pain_kind` for FailureEvent names) — drive breaches other than health, anticipated pain, tool frustration and exhaustion are never `pain`; new code asking "is it pain?" reads `kind`, never re-derives it from `pain_type` + `source` (older consumers still re-derive; their migration is the deferred nociception-layer plan, `docs/plans/deferred/nociception_layer.md` (PR #878), and the cluster-fear allowlist `DEFAULT_CLUSTER_FEAR_FAILURE_MODES` stays the authority on what is FEARED, `drive:oxygen` included). `failure_pain_kind` and the embodiment delta filter share ONE parser, `drive_failure_sensor` (a band-less `drive:x` is a standard failure, i.e. harm). Novelty is `agent_loop.situation_novelty` (`1 − best similarity`, `-1` unmeasured) of the proposal's `cluster_margins`, recorded at encode time because the encoder's per-modality stash is overwritten by the next tick. Salience stays `None` on purpose: the tag already scores pain and drive pressure separately. Those cluster ids ARE ATL concept ids (`SensorEncoder` registers them), so `ConceptExtractor._link_situation` adds the trace to the EXISTING concepts' `memory_refs['hippocampus']` — it never creates one, forms no inline relationships for them, and warns once per modality when a cluster is missing from the ATL. This is the substrate-native cue survival memory lacked: survival percepts carry no text, so name-keyed extraction never reached the situation. `EpisodicMemory.situation` persists; compression drops it (as it drops the refs). **The refs are a derived, LOSSY index; `EpisodicMemory.situation` is the durable key:** a compressed ATL concept (`CompressedSemantic`) holds no refs (warned once per modality), and `Concept.MAX_REFS_PER_LAYER` evicts by insertion order, which after a reload is sorted uuid order, not age — so a retrieval built on the links (2S-d) must fall back to, or rebuild from, the records' `situation`. Side effect, stated: the added refs count toward ATL retention centrality (`ref_count` in consolidation / eviction scoring); no action-selection path reads them. Regression guard: [tests/unit/test_memory_2sb_situation.py](../../tests/unit/test_memory_2sb_situation.py) + [tests/unit/test_memory_2sc_signals.py](../../tests/unit/test_memory_2sc_signals.py) + the real-loop composition in [tests/unit/test_water_trial_smoke.py](../../tests/unit/test_water_trial_smoke.py) (the executed escape's trace carries the water cluster and the water concept links back).

- **[engineering] Recall/lookup completion against the EC goes through `pattern_complete_readonly`; `pattern_complete_or_separate` is the ENCODE path** (D8, 1.2 gate 3 — measured 2026-09-05, verdict `separate-required`: one session-scale recall workload through the mutating path moved centroids past the frozen 0.98 cosine bound and incremented member counts, conflating query traffic with observation evidence in `ec_merge`'s count-weighted mean). - **[engineering] A bundle ingested with `require_signed=True` is REFUSED (`IngestRefused(duty="signature")`) unless its manifest carries a valid `ed25519` signature from a `--trust-key` signer** (1.2 P2P Slice A) — refusal, never admit-with-clamps, the same rule as the V1 front door. The signature covers the signature-excluded manifest PLUS the raw slice bytes (`hivemind/signing.py::bundle_signing_payload`), so a byte-tamper, wrong key, untrusted signer, or unknown algorithm all fail; `ed25519` is the only implemented algorithm (unknown → refuse). Signing is an optional `[sign]` extra (`cryptography`) imported through `optional_deps.py` — the base ingest/compose path never requires it, and unsigned bundles still ingest when `require_signed` is not set (the experimental tier). Regression guard: [tests/unit/test_hivemind_signing.py](../../tests/unit/test_hivemind_signing.py) (sign→verify round trip + tamper/wrong-key/untrusted/unknown-algo rejection + the ingest refuse-vs-admit pair).
- **[engineering] The Oasis substrate exchange has two tiers, and a contribution's ARRIVAL promotes nothing** (1.2 P2P Slice B). `hivemind/store.py::OasisStore` keeps `releases/` (Queen tier) and `experimental/` (received contributions) as separate disk trees, content-addressed by the bundle's sha256. `publish_release` REFUSES an unsigned manifest — a release is signed by definition, enforced at the store door, not by downstream convention. `accept_contribution` validates only that the bytes are a well-formed bundle, tags them with provenance (self-declared `contributor_id` AND transport `source` — different facts), and stores them in the experimental tier; it NEVER merges, ingests, or promotes to `releases/`. Promotion (running the V1–V10 `ingest_bundle` gauntlet + re-signing) is a separate gated Slice D operation. The endpoints (`hivemind/oasis_endpoints.py`) mount on the leader proxy's `/v1/substrate/*` and are inert (an authenticated 404) until a leader is handed a store (`start_leader_proxy(oasis_store=…)`), so an ordinary leader gains no new *capability* (only a bearer-gated feature-probe); the production caller that injects a store (`maxim oasis serve`) is Slice C, so the surface ships DORMANT until then. The accept path is serialized (`OasisStore._accept_lock`) because the proxy is threaded — a concurrent read-modify-write on the provenance log otherwise silently drops an audit record; a present-but-corrupt log fails loud rather than being reset-and-clobbered. The client transport is `hivemind/substrate_client.py` (its own file, over `utils/http` — the typed-peer-transports rule). ## 4. Live gotchas / known gaps

- **Isolated-vs-sequential drift detection** (from the centroid-drift lesson): any new EC modality or encoding path must be measured both ways — fresh EC per item AND one EC streaming all items. Sharp disagreement is the diagnostic signature of progressive centroid drift; do not ship on isolated-only numbers.
- **NAc decay is tick-anchored, not wall-clock — with ONE exception:** in-session NAc decay (`decay_eligibility`, `decay_reward_biases`, cluster-bias tau) runs per loop tick; NAc's only wall-clock decay is `NAc.load()`'s decay-on-load, and even that must be skipped (`apply_decay=False`) at `--resume-sim` and read-only observers. **Memory forgetting is NOT tick-anchored** (corrected 2026-09-21; this bullet used to say NAc's load was the ONLY wall-clock decay): Hippocampus `sleep()` removal/compression, promotion-pressure decay and ATL `consolidate`/eviction all run on `time.time()` against `accessed_at`, so downtime counts as disuse. The generic `--sim` loop skips `sleep()` (lightweight session end), but the survival harnesses and persistent orchestrator agents run the full one — any change to `sleep()` lands in the survival campaigns' own path. The redesign is [docs/plans/memory_strength_and_forgetting.md](docs/plans/memory_strength_and_forgetting.md). The **experience clock** the redesign runs on exists (Phase 2a): `Hippocampus.experience_clock`, advanced by the agent's WORLD time once per live loop pass by `runtime/experience_time.py::ExperienceClockDriver` (elapsed monotonic time minus paused time in real-time worlds; a fixed quantum per world turn in turn-based text worlds, declared by the percept source), persisted in `hippocampus.json`. Since Phase 2c-3 `StrengthStrategy` READS it (invariant above) — under `memory.strategy=strength` only; the default path is still wall-clock. Scripted harnesses that bypass the loop do not advance it until Phase 2S (a strict red gate holds that), which is exactly what `ExperienceClockStalled` makes loud rather than silent.
- **SCN oscillator runs on one input channel of six:** only `tool` TemporalEvents have a producer; the drive emitter is unwired AND malformed (dies in a silent `except Exception` swallow) — do not wire the distributor without also fixing the constructor call, and vice versa. ## 4b. Naming conventions — cross-system consistency (rehomed from AGENTS.md, 2026-08-19)

When multiple systems share a functional role they **must** use the same method and
property names — the `MemoryLayer` protocol maps cleanly onto concrete
implementations only because the names match. If two modules perform the same
operation, name it identically; don't invent synonyms.

| Operation | Canonical name | DO NOT use |
|---|---|---|
| Full sleep-cycle management (compress + remove + preserve) | `sleep()` | `cleanup()`, `gc()` |
| Promote important memories to long-term | `consolidate()` | `promote()`, `commit()` |
| Store a new record | `capture()` / `store()` | `add()`, `insert()`, `create()` |
| Retrieve by ID | `get()` | `fetch()`, `find_by_id()` |
| Query by filters | `recall()` | `search()`, `query()`, `find()` |
| Persist to disk | `save()` / `load()` | `dump()`, `serialize()`, `write()` |
| Internal association graph | `graph` (property) | `_graph`, `get_graph()` |
| Layer identifier | `layer_name` (property) | `name`, `type`, `kind` |
| Record access tracking | `touch()` | `update_access()`, `mark_read()` |

**Extending:** add the canonical name here before implementing a new shared
operation; rename inconsistent legacy names during the next change to that system.
