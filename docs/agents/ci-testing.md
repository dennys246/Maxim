> Part of the CLAUDE.md satellite layer. ## 1. Mental model

**Where the time goes (measured 2026-10-16).** The suite is 15,427 tests (unit 14,508, substrate 352, integration 336, behavioral 173, other 58). CI's `unit-tests` job takes a median 38.6 min: the fast suite step alone is ~34.7 min because it runs serially under `--cov --cov-branch`, and install is ~3.1 min, of which ~2m50s was `llama-cpp-python` building from sdist on every run, because nothing cached pip. Since #1318 every job that installs the package has its own exact pip cache and `llama-cpp-python` is pinned exactly (§3). A local `scripts/suite_at_commit.sh` run is estimated at 50–60 min. `pytest-xdist` is installed (the `[test]` extra and CI's pip line) but no run uses it: the suite runs serially again (see the xdist trial below). A handful of slow tests dominate: 11 tests at ≥5 s were 44% of a serial sample's time.

**The xdist trial (M22) ran and was reverted; this paragraph is the single source for its outcome.** #1339 (merged 2026-10-17) ran the fast suite under `-n auto --dist loadfile`; the trial's own fast-suite run took 17m45s (run 39072778282: `16198 passed … in 1065.33s`) against ~35 min serial. #1359 (2026-10-18) reverted it because **coverage is test-order dependent**: two serial runs on one commit and one machine, forward and reversed file order, differed by up to 16 missing statements in a package (34 in total), and `--dist loadfile` reshuffles the order on every run, so the exact-pin coverage ratchet flaked (`main` went red on `maxim/models`). #1339's pre-registered merge condition (per-package |Δmissing| ≤ 2 against serial) was not met either (maximum 11, `maxim/runtime`). The trial also surfaced three determinism defects, fixed and kept after the revert: #1349 (no test may leave a `scripts/` module replaced in `sys.modules`), #1356 (no `importlib.reload` in tests) and #1360 (the orchestrator golden pinned a wall-clock-decayed NAc value). Re-landing xdist is blocked on M60 (a coverage ratchet that tolerates the measured order noise), after the 1.3.3 release. Until then serial is the reference.

**What CI catches that local runs do not.** In the last 40 merged PRs, CI caught **zero functional test failures**: 9 of its 10 failures were the coverage ratchet (7 exact-pin or rise-above-floor bookkeeping, often after merging `main` or because macOS and Linux measure differently; 2 real gaps) and one was the PR-title lint. So the local suite is where defects are found; CI is where the coverage measurement, the Linux environment, the network namespace and the diff-scoped lints are authoritative.

**The gating surfaces.** A PR merges on the required checks `unit-tests`, `lint` and `Release build (wheel contents + version)` (`scripts/repo_settings_expected.json`), plus ruleset gates (CodeQL alerts) that `gh pr checks` does not render. `scripts/pr_merge_readiness.py <N>` reads all of them. A check that never ran looks exactly like one that passed (CLAUDE.md's green-PR lesson). Every merge re-runs the full workflow on push to `main`. The PR trigger includes `edited` (for base retargets), so a title or body edit also restarts a ~38-min run. The superseded run is cancelled, not failed: the script judges only the latest run of each check (name + app), as GitHub's gate does (#1442).

**Final full-suite run (owner decision 2026-10-16, not yet in force).** The owner adopted "CI's green, non-cancelled `unit-tests` run on the PR's head SHA counts as the final full-suite run". It takes effect when backlog row M64 makes `pr_merge_readiness.py` assert it. Until then CLAUDE.md's rule stands: the last full local suite runs on the exact commit pushed.

## 3. Invariants & lessons

**[engineering] Confirm the expected checks are PRESENT, not just green** (core rule in CLAUDE.md). Read a failing check's own output before applying a remembered remedy. Regression guard: [scripts/pr_merge_readiness.py](../../scripts/pr_merge_readiness.py) + [tests/unit/test_pr_merge_readiness.py](../../tests/unit/test_pr_merge_readiness.py).

**[engineering] Touch it, shrink it: a change that edits lines inside a function pinned over 200 lines must leave it smaller by at least that many lines** (owner decisions 2026-10-16). It applies to every pinned function; the reason is to keep god functions shrinking in the moment, not only in decomposition slices. Move the code you touched out (a helper, a phase, a module), so the extraction carries the edit. An urgent fix that cannot carries a `touch_exemptions` record in `src/maxim/utils/function_length_baseline.json` whose `touched`/`from`/`to` match the lint's printed numbers exactly. Never shrink by deleting comments or docstrings (counted, but review refuses it). A repo-wide rename or a formatter upgrade may need one record per pinned function: that is expected, not a defect. Moving a function between nesting levels or renaming it touches nothing; re-indenting a block inside it (a new `try:`/`with`) touches every re-indented line, so extract the block instead. An edit inside a nested pinned function is charged to every pinned function around it too. The attention-only residuals are mechanization backlog M67 in [outstanding.md](../plans/outstanding.md). Regression guard: [scripts/lint_function_length.py](../../scripts/lint_function_length.py)::touch_rule + [tests/unit/test_lint_function_length.py](../../tests/unit/test_lint_function_length.py) (the `test_t_*` tests, each proven by a deletion probe).

**[engineering] Coverage is measured once, in CI's fast-suite run, by the exact-pinned coverage version, and the local pre-check uses CI's own command.** Nothing may sit between the measuring suite and its gate except the MemoryHub step. Regression guard: [scripts/lint_coverage.py](../../scripts/lint_coverage.py)::ci_step_rules + [tests/unit/test_lint_coverage.py](../../tests/unit/test_lint_coverage.py)::test_the_suite_script_measures_with_cis_own_command.

**[engineering] Every CI test run is inside the loopback-only network namespace, and no install step swallows its failure.** The package installs WITH its core dependencies (#1188: a transitive-only dependency vanished and `main` went red at an unchanged commit). Regression guard: [tests/unit/test_ci_workflow_shape.py](../../tests/unit/test_ci_workflow_shape.py)::test_every_test_run_is_inside_the_loopback_only_network_namespace, ::test_no_install_step_swallows_its_failure, ::test_no_job_installs_the_package_without_its_core_dependencies; positive control [tests/unit/test_network_boundary.py](../../tests/unit/test_network_boundary.py).

**[engineering] Every job that installs the package has its own exact pip cache, and `llama-cpp-python` installs exactly pinned and built portable** (#1318). `actions/cache` on `~/.cache/pip/wheels` (the wheels pip builds, not its multi-GB downloads: the repo is at its 10 GB cache cap), keyed on the job (`github.job`), the Python version and `hashFiles(pyproject.toml, .github/constraints/*.txt)`, with no restore-keys. The nightly lanes cache inside `.github/actions/model-cache-setup`. setup-python's own `cache: pip` is banned: its key has no job in it, so a 4-minute job saved the shared entry first and `unit-tests` never got its llama wheel (review BLOCKER). The pin (`.github/constraints/ci-backends.txt`, also for any extra that pulls llama) is what keeps the cache safe, since an upgrade is a reviewed edit of a key file. `GGML_NATIVE=OFF` lets a wheel built on one runner CPU run on another. `lint` stays uncached so `scripts/prepr.py` can replay it; `release-build` stays uncached so a release never reads a cache; `aarch64-install` installs inside a container; R2's `extras-matrix` resolves one extra cleanly at floor/latest pins by design and builds nothing from an sdist. Regression guard: [tests/unit/test_ci_workflow_shape.py](../../tests/unit/test_ci_workflow_shape.py)::test_every_job_that_installs_the_package_has_its_own_exact_pip_cache + ::test_llama_cpp_python_installs_exactly_pinned_and_portable + ::test_the_lint_job_stays_reproducible_by_prepr.

**[engineering] A skip for a missing REQUIRED extra is a failure** (`--require-extras=console,sign`), so the console and signed-bundle tests cannot silently skip on every lane. Regression guard: [tests/conftest.py](../../tests/conftest.py)::_fail_required_extra_skip.

**[engineering] A release ships only the pinned, newest-for-its-contract pulse Console** (R4, #1333). `scripts/console_ui_pin.json` names the tag, commit, contract, asset sha256 and file digest. `vendor_console_ui.py` refuses any other bundle, and `--verify-pin` proves the pin is the newest stable pulse tag for the backend contract. It runs on a releasing PR and, from #1372, in the publish workflow. `audit_release_build.py` re-checks the built wheel and sdist against the pin, with no waiver. `release-build` builds every PR with the real pinned bundle, cached by the pin, instead of a stub. A contract drift is a CI warning on a non-releasing tree and a refusal on a releasing one; the definition of "releasing" lives in `check_nightlies.releasing`. Design: [r4_console_vendor_gate.md](../plans/archive/r4_console_vendor_gate.md). Regression guard: [tests/unit/test_vendor_console_freshness.py](../../tests/unit/test_vendor_console_freshness.py) + [tests/unit/test_audit_release_build.py](../../tests/unit/test_audit_release_build.py) + [tests/unit/test_ci_workflow_shape.py](../../tests/unit/test_ci_workflow_shape.py)::test_release_build_vendors_the_pinned_console_and_audits_it_without_a_waiver.

**[engineering] PyPI publishing happens only from `.github/workflows/release.yml`, on a signed annotated `v*` tag on main, after the owner approves the `pypi` environment** (#1372). No token is stored (OIDC trusted publishing), and only `publish` holds `id-token: write`. Every step runs with pipefail. The digests are job outputs, re-checked before use. The tag, the nightly (`check_nightlies.py --at`) and the console pin are re-checked after the approval wait, and the upload is proven against what PyPI serves. `check_release_tag.py` refuses a tag that is not the release, a `pypi` environment without a required reviewer, and a missing `v*` tag ruleset. Design: [release_pipeline.md](../plans/archive/release_pipeline.md). Regression guard: [tests/unit/test_release_workflow_shape.py](../../tests/unit/test_release_workflow_shape.py) + [tests/unit/test_check_release_tag.py](../../tests/unit/test_check_release_tag.py).

**[engineering] The `release-build` nightly check runs on `pull_request` only** (#938). On push and schedule it ran inside the very nightly it waits for, so main read red between a release merge and its tag. The release PR, and the publish workflow (`--at` the tag), are where it guards a release. Regression guard: [tests/unit/test_check_nightlies.py](../../tests/unit/test_check_nightlies.py)::test_the_release_build_job_runs_it_on_pull_requests_only.

**[engineering] Each required status check maps to exactly one job with no job-level `if:`** (a skipped required check counts as passing). Regression guard: [scripts/check_repo_settings.py](../../scripts/check_repo_settings.py) `--static` + [tests/unit/test_check_repo_settings.py](../../tests/unit/test_check_repo_settings.py).

**[engineering] A push to `main` is judged by the diff-scoped lints against the last push whose job passed**, not `before` (a cancelled pending run would otherwise skip a range). Regression guard: [scripts/_lint_git.py](../../scripts/_lint_git.py)::push_base + [tests/unit/test_lint_git_push.py](../../tests/unit/test_lint_git_push.py).

**[engineering] No test may leave a `scripts/` module replaced or removed under the name `import` resolves it to.** Load a private copy under a private name, or register it with `monkeypatch.setitem`. A script's lazy `from _provenance import …` otherwise sees a different object from the one a later test patched, so outcomes depend on which files ran earlier on that worker (hidden when the suite runs serially, exposed by xdist in #1339). The guarded names are `scripts.<module>` plus every module name under a `sys.path` entry inside `scripts/`, read from the live `sys.path`; a leak fails the test, the module or the collection, and the original entry is then restored. Blind spots: `importlib.reload` (same object, contents replaced; banned separately, see the next stub); a first import and a replacement inside one checked window; session- and package-scoped fixtures; scripts loaded from another tree; namespace-package directories (their submodules are guarded). Full history: [docs/lessons/script-module-identity-leak.md](../lessons/script-module-identity-leak.md). Regression guard: [tests/script_module_guard.py](../../tests/script_module_guard.py) + [tests/conftest.py](../../tests/conftest.py)::_scripts_modules_not_replaced (and `_scripts_modules_not_replaced_by_module`, the `pytest_make_collect_report` hookwrapper) + [tests/unit/test_script_module_guard.py](../../tests/unit/test_script_module_guard.py).

**[engineering] No test may `importlib.reload` a module.** A reload re-runs the module body inside the SAME object, so names other tests imported earlier (classes, functions) go stale: `pytest.raises(X)` misses the redefined `X`, and the outcome depends on which files ran earlier on that worker (#1350, exposed by xdist in #1339). Reset module state with the module's own test helper (e.g. `lane_backends._reset_lane_env_applied`) or `monkeypatch.setattr`. Blind spots: dynamic `__import__`/`getattr` spellings. Full history: [docs/lessons/script-module-identity-leak.md](../lessons/script-module-identity-leak.md). Regression guard: [tests/unit/test_no_module_reload.py](../../tests/unit/test_no_module_reload.py)::test_no_test_reloads_a_module.

## 4. Live gotchas / known gaps

- **A PR that fails `scripts/lint_coverage.py`:** raise the floor it names (`scripts/coverage_floors.json`), cover the changed lines it lists, or append a ref'd ledger entry (`scripts/coverage_exclusions.json`); the rules are in the lint's docstring. A rise above an exact pin after merging `main` is the bookkeeping class being redesigned (M60); do not hand-re-pin from a macOS number.
- **Per-file coverage floors (format v2, 2026-10-13):** `coverage_floors.json` also carries an opt-in `files` map (`"src/maxim/....py": {percent, missing}`) enforced beside the package floor, so a PR can have to edit a file pin as well as a package pin. Full rules (normalization, hysteresis, renames, the v1 → v2 change): section 1b of the `scripts/lint_coverage.py` module docstring.
- **Decomposing a function over 200 lines (`_run_agentic_loop_body`, `start_simulation_mode`, `_main_impl`, …):** each slice edits `src/maxim/utils/function_length_baseline.json` in the same commit — the procedure, with a worked example, is the "Baseline edits per decomposition slice" paragraph of `scripts/lint_function_length.py`'s docstring. The swallow lint credits moves the same way: a `try` moved verbatim is free, and one edited on the way needs a `scripts/swallow_moves.json` record naming its source (`scripts/lint_no_silent_swallows.py`, move credit). For `run_agentic_loop` (1.3.2), the gates every slice must keep green unchanged, the golden regeneration rule and the function-specific pins are in `docs/plans/roadmap_1_3_x.md` §"The decomposition"; "the loop contains X" pins read `tests/unit/_loop_source.py`.
- **A test that needs a credential-shaped fake** (an API key, a `Bearer` header, a PEM header) trips `scripts/lint_secrets.py` on every path: build the fake at runtime from pieces (the `fake()` helper in `tests/unit/test_lint_secrets.py`), or land an entry in `scripts/secret_scan_allowlist.json` on `main` first; the rules are in the lint's docstring and in docs/agents/simulation-experiments.md.
- **New opt-in env vars in hot startup paths need autouse conftest scrubs in the same commit** — a test that sets the var leaks the side effect into every later runtime-constructing test (once cost a 9-minute hang on a real 1 GB model download). Template: the existing `_isolate_maxim_*` fixtures in [tests/conftest.py](../../tests/conftest.py). The ~54 autouse fixtures cost under a minute of suite time in total (2026-10-16). Full history: [docs/lessons/env-var-autouse-scrubs.md](../lessons/env-var-autouse-scrubs.md).
- **`scripts/ci_netns.sh` carries the job's environment by NAME (`sudo --preserve-env=<list>`), never `sudo -E`:** Ubuntu 26's sudo-rs ignores `-E`, which from 2026-10-20 silently emptied every netns lane's job variables (O20; the tts cells and both nightlies went red, unit-tests stayed green without them). The innermost shell fails with exit 3, naming what was lost, if any preserved name does not arrive. Don't put values on `sudo`'s argv (a long-lived process: secrets would show in `ps`), and secret-shaped names (`*TOKEN*`, `*_KEY`, `*SECRET*`, `*PASSWORD*`) stay out. Pinned by `tests/unit/test_ci_workflow_shape.py::test_the_netns_script_carries_the_callers_environment_by_name_and_checks_it_arrived` and, by behaviour (the real script over stub sudo/unshare/setpriv), `::test_the_netns_arrival_check_passes_a_carried_environment_and_refuses_a_dropped_one`.
- **A tree-scanning lint is tested with its own new files tracked:** run it after `git add -N <new files>` (#1175 was green only because its test file was untracked).
- **Run `scripts/prepr.sh` on the last commit before pushing, and let it finish.** It runs every `jobs.lint` step plus the targeted mypy step, read from test.yml, and scans the PR title/body as CI does. Exit codes: 0 PASS · 1 FAIL · 2 REFUSED (it cannot reproduce CI's verdict: behind or stale origin/main, dirty tree, pin or python mismatch, PR-text mismatch, an unreproducible workflow construct) · 3 TAINTED-PASS (passed under `--allow-*`, `--no-fetch`, `--no-pr` or typed PR text). Only 0 clears a push; a `NOTE:` platform line does not change the code. Before a PR exists, pass `--title` (taints) or `--no-pr`. `--list` prints the plan (M59).
- **Stale timing comments in test.yml:** the concurrency block's "~12 min of real work" and the `unit-tests` timeout comment's 18:26/26:46 figures predate the 15k-test suite; the 2026-10-16 numbers are in §1. The `timeout-minutes: 60` has ~20 min of headroom over the median.
- **The mypy file list lives only in `scripts/run_mypy_public.sh`** (M65); CI and CLAUDE.md call it, and `test_ci_workflow_shape.py` fails if a second copy appears.
- **Worktrees** (CLAUDE.md keeps the rule; the full text, moved from CLAUDE.md in the 2026-10-16 diet): **Parallel sessions use worktrees, and worktrees live under `.worktrees/`.** When ≥2 Claude sessions run concurrently on independent work, each uses its own git worktree — `git worktree add .worktrees/<branch-slug> -b <full-branch> origin/main` — and works entirely in absolute paths within it. Never a sibling directory (`../Maxim-wt-*`): `.worktrees/` is gitignored (so nested checkouts are invisible to `git status` and to ruff, which honors `.gitignore`), `pytest` is pinned out of it (`testpaths` + `norecursedirs` in `pyproject.toml`), and a nested tree sits inside a Claude session's primary working directory, so no extra permission scope is needed. Single-session work stays in the main checkout. Tests in worktrees need `export PYTHONPATH="$PWD/src"` (absolute, its own line — the installed editable package shadows the worktree otherwise). `git worktree remove .worktrees/<slug>` when the PR merges; `git worktree prune` for stragglers. Note `~/.maxim/` is shared across worktrees — don't run sims from concurrent doc/code sessions or they'll collide on persisted state.
- **Threading pitfalls** (moved from CLAUDE.md §Testing in the 2026-10-16 diet): use `threading.RLock` (not `Lock`) if a method acquires the lock then calls another method that also acquires it — regular `Lock` deadlocks on re-entry; thread-safety tests that appear to hang are usually deadlocked, not slow.
- **No-silent-swallows: the CLAUDE.md invariant, verbatim, before the 2026-10-16 diet** (CLAUDE.md keeps the rule; the check-by-check detail is also the lint's own docstring): **[engineering] No NEW silent exception swallows** — never add a bare `except Exception: pass`; narrow the exception type, or handle-and-log. A handler that assigns or returns a fallback without reporting is the same swallow (check 5, the silent-default shape). Existing sites predate the rule and are grandfathered at their per-FUNCTION count; a verbatim move is free, an edited move needs a `scripts/swallow_moves.json` record. The deleted `@resilient` decorator must not be cited or re-introduced. Regression guard: [scripts/lint_no_silent_swallows.py](scripts/lint_no_silent_swallows.py) in CI (shipped 2026-08-13, fail-loud Stage 4) — zero-total over the measurement-path files (its `MEASUREMENT_PATH` list) + diff-scoped no-count-increase repo-wide + no DE-INSTRUMENTATION (checks 3–4, 2026-09-23): a "report" is ONLY the Stage-1 form (`log_swallowed_exception()` or `site=`) — the explicit `(e, operation=...)` form is a DEBUG line with no event and does NOT count, so on the measurement path handle-and-log means Stage-1; compared PER FUNCTION (per-file counts let a burn-down mask a de-instrumentation elsewhere in the file), the unreported count may not rise on listed files and repo-wide reports may disappear only with their handlers — deleting a swallow is free, de-instrumenting one fails, including in a moved function; masking within ONE function remains a stated blind spot; [tests/unit/test_lint_no_silent_swallows.py](tests/unit/test_lint_no_silent_swallows.py) drives `main()` itself. And since 2026-08-29 it PRINTS the repo-wide total every run, so the count lives in the CI output rather than in a number here that rots; the ad-hoc review grep remains the belt for the evasion shapes the lint's docstring lists.
- **A golden that pins a value DECAYED per loop tick pins the wall clock:** the orchestrator golden's AUT loop keeps ticking every ~0.5 s for 120 s after any LLM submit, so a NAc bias saved at the stop had decayed by however many ticks fit before it (0.2 x 0.98^8 locally, ^7 in CI under load during the since-reverted xdist trial, run 39072778282; CI is serial again, but any slow enough machine trips it). `tests/unit/_orch_harness.py::_NAC_DECAY_PINNED` pins those maps by key, sign, bound and "decayed below the last write", and `nac_credits` pins every credit write behind them by value; pin causes, not tick-paced values, in any new golden.

### `scripts/suite_at_commit.sh` (moved from docs/lessons/development-flow-speed.md)

```bash
scripts/suite_at_commit.sh                     # the suite + the coverage ratchet at HEAD, in a throwaway worktree
scripts/suite_at_commit.sh <commit>            # ... at any commit
scripts/suite_at_commit.sh --no-cov <commit>   # the suite only: quicker, NOT the pre-push check
scripts/suite_at_commit.sh "$(git stash create)"  # uncommitted tracked work (no ref moved, no signature)
```

It creates a uniquely named `.worktrees/suite-<sha>.XXXXXX` under the MAIN checkout (so concurrent runs on one commit never share or delete each other's tree), prunes stale worktree records first, runs the fast suite and `test_memory_hub.py` there with an absolute `PYTHONPATH` (so the installed package cannot shadow it), prints the commit next to the result, and removes the worktree. No `-x`, deliberately: the full failure list is worth more than the first. It tests a commit by design: untracked files are exactly what it keeps out of the run. The result names the commit it tested; that is not evidence of which diff was REVIEWED. To clean up a stopped run, kill only the pytest whose cwd is your own `suite-<sha>` tree.

**Since M47 (2026-10-11) it is also the coverage pre-check.** By default the fast suite runs with CI's exact measuring command and is followed by `scripts/lint_coverage.py --local`, so `PASSED` also means the coverage ratchet passed. `--local` gates diff coverage (>= 80% of changed `src/maxim` lines) and the floors of the TOUCHED packages (changed `src` files, deletions and moves included, plus the packages the changed tests import); the overall floor, untouched packages and a PR's own floor-pin edits are printed as notes, because floors are measured in CI's environment. A touched floor breached within noise needs CI's number. The script checks the installed coverage version before the suite runs. #1201, #1213, #1232 and #1240 each failed CI on the ratchet because no local run measured coverage.
