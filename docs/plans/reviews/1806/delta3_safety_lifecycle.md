**Pre-answer for PR 1's "verify first" (D3, `wlan_ip` is `None`).** `reachy_mini.py::ReachyMini._configure_mediamanager` builds `MediaManager(signalling_host=daemon_status.wlan_ip or "localhost", daemon_url=self._daemon_http_url)`, and `media_manager.py::MediaManager._init_webrtc` dials `find_producer_peer_id_by_name(signalling_host, 8443, ...)`. With `wlan_ip` `None`, WebRTC signalling therefore goes to **`localhost:8443` on the Maxim host**, never to the dialled host. Only `daemon_url` (sound and files) uses the dialled host. `daemon_status` here is the **session's** `get_status()`, not step 1's REST read. The answer is "otherwise": force `no_media`.

## New findings

| E1 | **The restore order re-acquires on the foreign daemon.** If the snapshot is restored at the top of the divergence handling, "before `_drop_handle`", the generic `except` re-acquire check (`_mini is not None and flag`) still precedes `_drop_handle` and fires on a carried `True`. The result is `acquire_media()` POSTed to the session's unknown daemon, which can steal a deliberate release. **Fix:** the divergence path bypasses the generic re-acquire branch entirely: (1) `_mini.media_manager.close()`, (2) `_drop_handle()`, (3) restore the snapshot, (4) stop the tunnel. | E2 | **A backend flip across reconnects drops a carried release.** Connect A forces `no_media` (the `wlan_ip` probe fails) and owns the release. ## Evidence

1. **The flag's lifecycle** (`controller.py`): it is initialised `False` and assigned only at `self._media_released_by_connect = self._connect_released_media(status)`, right after `ReachyMini(`. The generic `except Exception` runs `if self._mini is not None and self._media_released_by_connect: self._reacquire_media(during="a failed connect")`, **then** `_drop_handle()`, then `_stop_ssh_tunnel()`. `_reacquire_media` clears the flag only on a confirmed `media_released is False`. `disconnect()` re-acquires only while `_mini is not None`. So after a dropped handle, a carried `True` waits for the next connect's `_connect_released_media`. That is the D1 intent, and the reason the order in E1 matters.
2. **The SDK's no_media path** (`reachy_mini.py`): `__init__` sets `self._media_released = False`, and then `_configure_mediamanager`. Under `"no_media"` it calls `release_media()` unless the session status reports `no_media`, which POSTs through `self.client` (the session's daemon) whatever that daemon's current state. `acquire_media()` rebuilds the manager with the SDK's stored `_media_backend`. A `default` handle never releases, and so never reports `media_released: True` (E2).
3. **Signalling host** (`reachy_mini.py::_configure_mediamanager`, `media/media_manager.py::MediaManager.__init__/_init_webrtc`): `signalling_host=daemon_status.wlan_ip or "localhost"`, port 8443. `daemon_url=f"http://{client.host}:{client.port}"`. `daemon/daemon.py` sets `wlan_ip=None` by default and fills it from `get_ip_address()` only on wireless daemons ("loopback-only configurations have no meaningful wlan_ip").
4. **Tunnel** (`controller.py::_start_ssh_tunnel`): it forwards only `-L 8000:127.0.0.1:8000`. 8443 is not forwarded.
