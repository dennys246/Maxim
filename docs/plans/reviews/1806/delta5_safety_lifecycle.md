## Evidence

1. **The SDK's NO_MEDIA selection** (`reachy_mini.py::_configure_mediamanager`). The order is: explicit `"no_media"` → NO_MEDIA (with `release_media()`); daemon `no_media` → NO_MEDIA; `default`/`auto` → LOCAL if `connection_mode == "localhost_only" and is_local_camera_available()`, else WEBRTC with `signalling_host = daemon_status.wlan_ip or "localhost"`. An explicitly named `local` backend → LOCAL whatever the mode (G1, G2).
2. **`is_local_camera_available`** (`daemon/utils.py`) tests only whether `CAMERA_SOCKET_PATH = "/tmp/reachymini_camera_socket"` exists and is accessible on the machine running the SDK. Nothing ties it to the daemon behind :8000 (G2).
3. **`wlan_ip`** (`daemon/daemon.py`): it defaults to `None` and is set by `get_ip_address()` only when `self.wireless_version` (G2a).
4. **The manual-tunnel guidance** (`controller.py::ReachyMiniController.__init__` docstring, `tunnel` arg, and the `_start_ssh_tunnel` failure log) says "start the tunnel manually and set `tunnel: false, connection_mode: localhost_only`". Under `tunnel=True`, `connect` also sets `effective_mode = "localhost_only"` (G2).
5. **The flag lifecycle** (`controller.py::connect`). `status` is read once, before `ReachyMini(`. `_media_released_by_connect` is assigned only after `ReachyMini(` returns. The generic `except` re-acquires only when `_mini is not None`. With v6's (i)–(iii), no path leaves a stale True (F1); `before` remains the pre-E2 value (N1).
6. **Camera-absent handling** (`controller.py::connect`). `_video_stream = None` when `media.camera is None`, so the G1 run is honestly blind and does not fake frames.
