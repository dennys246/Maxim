## Evidence

1. **The divergence path cannot reach the foreign daemon** (`controller.py`). `_drop_handle` swaps `_mini` to `None` and calls only `client.disconnect()`. Its docstring says `media_manager.close()` is not mirrored there, so the explicit close in E1's order is needed and harmless. `disconnect()` gates its re-acquire on `self._mini is not None`. SDK `reachy_mini.py`: `MediaManager.close()` closes only the local camera and audio objects, and `ReachyMini.__del__` only calls `client.disconnect()`. Only `__exit__` and `acquire_media()` POST `/api/media/acquire`, and the E1 path calls neither.
2. **The flag's lifecycle** (`controller.py::connect`). The flag is assigned only right after `ReachyMini(` returns. When `ReachyMini(` raises, `_mini` stays `None`, so the generic `except` skips `_reacquire_media` and the flag keeps whatever value it had before the call. That is why F1 (ii) and (iii) matter.
3. **A REST acquire is a confirmation** (`daemon/daemon.py::Daemon.acquire_media`, `daemon/app/routers/media.py`). The route awaits `acquire_media()`, which sets `_media_released = False` and `_status.media_released = False` (or no-ops when there is nothing to acquire), and only then returns `{"status":"ok"}`. `io/ws_client.py::_media_request` treats any non-2xx as failure.
4. **The SDK still releases on a carried `no_media`** (`reachy_mini.py::_configure_mediamanager`). Under `"no_media"` it calls `release_media()` whenever the daemon status lacks `no_media` and the SDK's own `_media_released` is `False` (always `False` at `__init__`). So `mini.media_released` is `True`, and the carried branch of `_connect_released_media` keeps ownership. This is the E2 fallback, which holds.
5. **The reconnect already degrades honestly** (`embodied_runtime/connection.py`). `_soft_reconnect` → `_restore_capabilities` re-derives `has_vision`/`has_audio` from the robot's media state (the 2026-08-01 fold). The controller's connect sets `_video_stream = None` when `media.camera is None`.
6. **`wlan_ip` is set only on wireless daemons.** `daemon/daemon.py` leaves `wlan_ip=None` by default and fills it only on wireless daemons, so loopback (`localhost_only`, Lite) daemons always report `None` (F4).
