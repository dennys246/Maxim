**Verdict: PARTIAL.** The decision is right and closes the explicit `connection_mode: network` + `local` case. But "effective `connection_mode`" is not defined at load time for three inputs, and each of them lets an explicit LOCAL (or a LOCAL alias) reach `ReachyMini(` while the robot is remote. All three are fail-open, and all three are new to this bullet.

## Confirmed (no defect)

- **Absent key.** `selfy.py` builds `_connect_config` without `connection_mode`, and `ReachyMiniController.__init__` defaults to `connection_mode="network"`. An absent key is therefore effectively `network`. The load check must apply that default, so an entry that omits the key but sets `local` is refused. This is well defined, but the bullet should state it so the loader does not treat "absent" as "unknown, allow".
- **Legacy `localhost_only:` bool.** The controller signature has no `localhost_only` parameter, so `connect_robot` filters the key out and the mode stays `network`. That is consistent with the rule.
- **The LOCAL alias set is `local`, `gstreamer`, `gstreamer_no_video`, `sounddevice_no_video`, `sounddevice_opencv`** (`media_manager.py` `_DEPRECATED_ALIASES`). `MediaBackend.DEFAULT = LOCAL` in the enum is never reached for the strings `default`/`auto`, because the SDK special-cases them first. In network mode they resolve to WEBRTC. An unknown string falls back to auto-detect, which is LOCAL only in `localhost_only`.
- **Other legacy flows.** No `src/` caller passes a LOCAL-family `media_backend` (all defaults are `"default"`), and no shipped YAML sets one. The only legacy break is the one the bullet already names, plus `auto` + `local` if M9-1 is folded.

## Evidence

- SDK `reachy_mini.py::_initialize_client`: `auto` tries `localhost` and sets `selected = "localhost_only"`. If that fails it tries `self.host` and sets `selected = "network"`. `self.connection_mode` is the selected value.
- SDK `reachy_mini.py::__init__`: `self.media_manager = self._configure_mediamanager(media_backend, log_level)` runs inside the constructor, before control returns to Maxim.
- SDK `_configure_mediamanager`: an explicit backend string goes through `MediaBackend(media_backend.lower())`, which honours LOCAL in any mode. `default`/`auto` give LOCAL only when `self.connection_mode == "localhost_only" and is_local_camera_available()`.
- SDK `_normalize_connection_mode`: `normalized = connection_mode.lower()`, and `ValueError` outside the three values.
- controller.py `connect`: `effective_mode = self._connection_mode`, then `if self._tunnel: ... effective_mode = "localhost_only"`. `ReachyMini(connection_mode=effective_mode, media_backend=self._media_backend)` passes both verbatim.

## Stop-rule outcome

**STOP RULE NOT MET.** M9-1, M9-2 and M9-3 are fail-open (wrong-body camera on a remote robot) and not in an already-covered class. All three fold into the one bullet: define "networked for the media rule" as *not (normalised mode == `localhost_only` and not `tunnel: true`)*, apply the absent-key default of `network`, normalise with `.lower()`, and add red gates for `auto` + `local`, unpinned `tunnel: true` + `local`, and `Network` + `local`. A delta-scoped confirmation of that fold is owed.
