## Evidence

1. **The attribute.** `reachy_mini.py::ReachyMini.media` returns `self.media_manager`. `media/media_manager.py::MediaManager.__init__` sets `self.camera = None` before its `match`. The `NO_MEDIA` arm only logs. `close()` resets `camera` to `None`, so after a `release_media()` (which calls `media_manager.close()`) it is `None` too (G1).
2. **The two NO_MEDIA routes.** `_configure_mediamanager`: an explicit `"no_media"` (from `.lower()`) → NO_MEDIA, plus `release_media()` when the daemon is not `no_media`; a daemon `no_media` → NO_MEDIA. Both leave `camera` `None` (G1 holds for the routes it names).
3. **Lazy failure.** LOCAL arm: `try: self._init_camera(...) except Exception: warning "continuing without camera"`. `_init_camera` assigns `self.camera` and *then* calls `open()`. `camera_gstreamer.py::GStreamerCamera.open` waits ≤2 s for `try-pull-sample` inside `try/except Exception: pass` and returns regardless. WEBRTC: `_init_webrtc` assigns `self.camera = webrtc_media` and then calls `open()`. `webrtc_client_gstreamer.py::GstWebRTCClient.open` is only `set_state(PLAYING)`. `webrtc_utils.py::find_producer_peer_id_by_name` raises `KeyError` on a missing producer (fail-closed). `read()` returns `None` when no sample is available (H1).
4. **`get_hardware_id`** (`utils/hardware_id.py`). It returns `None` when `/sys/bus/usb/devices` does not exist (macOS). Otherwise it reads the text files `idVendor`/`idProduct`/`serial` for VID `38fb`, PID `1001`, catching `OSError` per device, and returns `sha256(serial)[:16]`. There is no device open, ioctl or USB claim. Probe on this Mac: `get_hardware_id -> None`, `/sys exists: False` (G2, N4).
5. **The daemon's id is the same call.** `daemon/daemon.py::Daemon.__init__` builds `DaemonStatus(..., hardware_id=get_hardware_id())`, which is host-scoped and independent of sim mode. So on the robot the local call equals the reported id (with the same SDK minor, which step 1's era/minor check enforces). A sim daemon on a host with a Lite attached would report the real id, but step 1's `refusal` already rejects sim/mockup flags (G2).
6. **Connection modes.** `_initialize_client`: `"network"` dials `self.host:port` (so `127.0.0.1:8000`, i.e. the tunnel); `"localhost_only"` dials `localhost`. LOCAL under `default`/`auto` requires `connection_mode == "localhost_only" and is_local_camera_available()`, so network mode never auto-selects LOCAL. An explicitly named backend is honoured whatever the mode (H2). Under network mode `signalling_host = wlan_ip or "localhost"`, so E4's `wlan_ip`-None rule is exactly what keeps a manual tunnel off `localhost:8443`. A manual tunnel to a wireless robot (non-None `wlan_ip`) falls to the existing same-pin probe at `wlan_ip:8000` (G2 coherent).
7. **The controller** (`controller.py` @ b7380ee7). `connect` assigns `_media_released_by_connect` right after `ReachyMini(`. Its generic `except Exception` re-acquires only when `_mini is not None and _media_released_by_connect`, then returns `False` (N3). `_has_cam` is derived only from `camera is None` (H1). `get_doa_reader` branches on the `localhost_only` label (N5).

## Stop-rule outcome

**Not met.** H1 and H2 fail open. Both are in already-covered classes (H1: E5 strict perception / G1; H2: R4-1 wrong-body media), and neither moves a joint. N3–N5 fail closed. The fold is one sentence plus red gates for each: a first-frame postcondition (H1), and "not proven onboard" replacing "not `localhost_only`" in the load-time allowlist, with an explicit-`local` gate (H2). A delta check limited to those two should then meet the stop rule.
