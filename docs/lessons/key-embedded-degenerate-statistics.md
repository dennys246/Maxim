**[engineering] Key-embedded values produce structurally-degenerate statistics** (Wire 1 pre-merge fold, 2026-05-17): if your statistic accumulator's KEY embeds the very dimension you want the statistic to vary over, the per-key statistic is structurally 0 (or degenerate) on every binary-input case. Wire 1 originally placed reward-outcome variance on `CausalLink`, but `CausalLink._generate_link_id` keys on `outcome_signature` (which embeds valence as part of the key). Per-link reward variance was therefore always 0 for binary success/failure observations — every `CausalLink` instance held one outcome class and the Welford accumulator never saw alternation. The fix moves variance one level up to `NAc._event_outcome_welford` keyed by `(agent_id, event_signature)` — the level where the cross-outcome distribution actually lives. **Rule:** before adding a statistic field to an entity, list the entity's key fields and confirm the statistic varies over them. If the value you're trying to measure is part of the key, the statistic accumulator belongs on the parent aggregation, not the keyed entity. Generalises beyond variance: bandit per-arm reward estimates, goal-conditioned success rates, anywhere "we measure how X varies given context Y" but Y is part of the index. The same trap as the `_context_similarity` denominator lesson — both are about silent degenerate-statistic shapes that the test suite reads as zero or one and concludes "feature works fine, value is just small". Reference: `docs/plans/archive/release_0_9_1.md` Stage 4 and the CausalLink class docstring. Regression guard: [src/maxim/decisions/nac.py](src/maxim/decisions/nac.py) — variance accumulator lives on `NAc._event_outcome_welford` (parent aggregation), not on keyed `CausalLink`; class docstring documents the move.
