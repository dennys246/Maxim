**[engineering] `utils/optional_deps.py` is the canonical optional-dependency surface** (2026-06-05, PR #341): historically each consumer of an optional package rolled its own `try: import X except ImportError: …` block with wildly inconsistent failure behaviour — some raised, some swallowed a WARNING, some failed silently. The canonical failure was `_AnthropicBackend._ensure_client` logging one WARNING and returning `None`, causing the router to treat the missing backbone as a transient hiccup; the whole sim completed at `cost=$0` with every action a `_llm_unavailable` fallback and no user-visible error. `maxim.utils.optional_deps` makes failure behaviour uniform and intentional through three entry points, each matching a specific intent: (1) **`require_optional_dependency(import_name, *, extra=None, feature=None)`** — use when the caller EXPLICITLY requested a feature (a configured cloud LLM profile, `--vision`, a selected TTS voice, a robot controller). Raises `OptionalDependencyError` (subclass of `ImportError`) with an actionable `pip install pymaxim[<extra>]` hint. The dedicated subclass lets fail-soft layers (the LLM router) distinguish "requested feature not installed → abort loudly" from "transient runtime failure → try next provider". (2) **`optional_dependency_available(import_name)`** — use for capability PROBES where absence is normal (GPU detection, "use X if present"). Returns a `bool`, never logs. (3) **`warn_optional_fallback(import_name, *, fallback, extra=None, feature=None, log=None)`** — use when there is a real working fallback (`sentence-transformers` → bag-of-words, `spacy` → identity decomposition, `ddgs` → regex scraping). Emits exactly ONE deduped WARNING per `(import_name, feature)` pair per process via `_warned_fallbacks`; the caller keeps the fallback path. **Do NOT add a new `try: import X except ImportError: pass` (silent), `except ImportError: logger.warning(...)` (non-deduped), or `except ImportError: return None` (swallowed) anywhere in `src/maxim/`.** Route through the appropriate entry point. The `EXTRA_FOR_IMPORT` dict in `optional_deps.py` maps import names to pyproject extras — add new entries there when adding new optional features rather than hardcoding hints at call sites. `OptionalDependencyError` access patterns are exactly three: `.import_name`, `.extra`, `.fix_hint`. Do NOT add `.raw_cause` or parallel attributes — the router branches on the dedicated type, not on message content. Regression guard: [tests/unit/test_optional_deps.py](tests/unit/test_optional_deps.py) — covers `require_optional_dependency` raise/return, `optional_dependency_available` bool, `warn_optional_fallback` dedup, `OptionalDependencyError` subclass shape, and LLM-router reraise behaviour.
