- **[engineering] `Tool.input_schema` is dual-format; `Tool.to_json_schema()` is the canonical export** (CC9, 2026-04-28). Tool authors may write either the legacy custom format (`{NAME: type}` / `{NAME: (type, default)}` / `{NAME: "description"}`) or JSONSchema 2020-12 (`{"type": "object", "properties": {...}, "required": [...]}`). `Tool.__init__` does NOT normalize — `input_schema` is left exactly as authored, so the `@maxim.tool` decorator's JSONSchema output and the legacy class-based custom-format tools coexist. **Format-sensitive consumers reading `tool.input_schema` MUST route through `tool.to_json_schema()`** rather than iterating `input_schema.items()` directly. Motivating bug class: pre-CC9, `runtime/agent_loop.py:2702-2722` iterated `input_schema.items()` and called `v.__name__` on each value — fine for custom-format, silent `AttributeError` swallowed by `except (KeyError, Exception): pass` for `@maxim.tool` tools whose values are JSONSchema property dicts. Result: every `@maxim.tool` tool silently rendered with empty params in the dynamic-tool prompt branch, and no test caught it because the failure path was a swallowed exception. The same silent-no-op pattern this codebase pushes structurally elsewhere — fixed by routing through `to_json_schema()` and pinned by `tests/unit/test_tool_dual_schema.py::TestAgentLoopParamRendering`. The custom format is strictly less expressive than JSONSchema (no `enum`, `pattern`, `format`, `oneOf/anyOf/allOf`, `additionalProperties`, nested object schemas) — authors needing those features must author JSONSchema directly. The description-as-value pattern (`{NAME: "description string"}`) is **legacy convention**: dispatches as required + emits `required: [NAME]` in the JSONSchema export, even when the description text says "Optional" — strict MCP / Anthropic clients will reject calls that omit the parameter, so new tool code should migrate to `{NAME: (str, None)}` + JSONSchema descriptions. **This contract is frozen at 1.0** — adding a third format or collapsing one is a breaking change. See `docs/plans/deferred/mcp_compatibility.md` for the broader 1.1+ MCP work this unlocks. Regression guard: [tests/unit/test_tool_dual_schema.py::TestAgentLoopParamRendering](tests/unit/test_tool_dual_schema.py) — pins both formats render correctly via `Tool.to_json_schema()`.
