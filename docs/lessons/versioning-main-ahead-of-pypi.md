# Versioning: `main` is ahead of PyPI (the policy's history)

The rule and its enforcement live in CLAUDE.md's `main`-is-ahead-of-PyPI invariant; the release procedure is
[docs/publication_guide.md](../publication_guide.md). This file keeps the policy's history, moved out of CLAUDE.md's
§Versioning in the 2026-09-27 diet (the section duplicated the invariant).

**Update 2026-10-28 (M83 step 3): `[Unreleased]` no longer accumulates.** Every PR appended at its top, which made `CHANGELOG.md` the commonest conflict between parallel PRs. A `src/` change now adds a `changelog.d/<slug>.<kind>.md` fragment, and the bump PR folds them in with `scripts/changelog_fragments.py assemble`. One check, `changelog_fragments.py check`, replaced both `lint_unreleased_on_src_change.py` and `lint_unreleased_declared.py`, and dropped the latter's in-flight-release path, because the tag now sits on the bump merge commit. The text below is the record as it stood; the current rule is CLAUDE.md's invariant. Design: [docs/plans/changelog_fragments_m83_approach.md](../plans/changelog_fragments_m83_approach.md).

## The CLAUDE.md §Versioning text, verbatim, before the 2026-09-27 diet (links relative to the repo root)

**Policy (decided 2026-08-29, roadmap 1.1.x item 16.1): `main` is ahead of PyPI; the bump happens in the release transaction.** Between releases `pyproject.toml` and `src/maxim/__init__.py` carry the LAST PUBLISHED version and `CHANGELOG.md` accumulates under `## [Unreleased]`; the bump commit (release PR) moves that section under `## [X.Y.Z] - <date>`, then build → publish → tag on the published commit → GitHub Release, per [docs/publication_guide.md](docs/publication_guide.md). The three living sync lines — in this file, `docs/plans/README.md` and `docs/index.md` — no longer assert what PyPI serves: they name the pyproject version and link https://pypi.org/project/pymaxim/ for the served one (dated CHANGELOG sections and release announcements stay historical records). A `src/` change still obliges a release cut eventually — the trigger is unchanged (runtime behavior, CLI interface, peer/leader protocol) — but it does NOT bump on the spot. **That half is now ENFORCED** — the card's Release-governance condition (4), a diff-scoped check that a post-tag `src/` commit adds an `[Unreleased]` line, shipped as [scripts/lint_unreleased_on_src_change.py](scripts/lint_unreleased_on_src_change.py) and closes roadmap 16.10. Enforced by [scripts/lint_version_sync.py](scripts/lint_version_sync.py) in CI: pyproject == `__init__` == a `## [version]` CHANGELOG header == the three version lines, which may carry no "pending"/"rc"/"serves" prose. Check locally: `python -c "from maxim import get_version_info; print(get_version_info())"` or `maxim peer version` (mismatch → the leader needs `maxim peer update && maxim peer restart`).

## The CLAUDE.md invariant and §Versioning, verbatim, before the 2026-10-16 diet (links relative to the repo root)

- **[engineering] `main` is ahead of PyPI: the version bump happens in the RELEASE TRANSACTION, not on the change that earns it.** Between releases `pyproject.toml` + `src/maxim/__init__.py` carry the last published version and `CHANGELOG.md` accumulates under `## [Unreleased]`; the release PR moves that section under `## [X.Y.Z] - <date>`, then build → publish → tag on the published commit → GitHub Release with the exact artifacts and ABSOLUTE links. The three living sync lines (this file, `docs/plans/README.md`, `docs/index.md`) NAME the `pyproject` version and LINK PyPI — they never describe what PyPI serves, because that prose drifted on every release. Written intent diverging from routine practice is the Codex card's definition of a D; this is the written intent. Full procedure: [docs/publication_guide.md](docs/publication_guide.md). Regression guard: [scripts/lint_version_sync.py](scripts/lint_version_sync.py) in CI (lint job, "Version sync" step) — `pyproject` == `__init__` == the NEWEST released `## [X.Y.Z]` CHANGELOG header == all three sync lines, none of which may carry "pending"/"rc"/"serves"/"published" prose in the version claim; [tests/unit/test_lint_version_sync.py](tests/unit/test_lint_version_sync.py). The `[Unreleased]`-accumulates half is ENFORCED too (roadmap 1.1.x item 16.10, CLOSED): [scripts/lint_unreleased_on_src_change.py](scripts/lint_unreleased_on_src_change.py) in CI (lint job) is diff-scoped — a `src/maxim/*.py` change that does not grow `## [Unreleased]` FAILS; [tests/unit/test_lint_unreleased_on_src_change.py](tests/unit/test_lint_unreleased_on_src_change.py).
