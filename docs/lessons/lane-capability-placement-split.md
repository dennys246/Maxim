**[engineering] Lane = capability tier; placement (origin) is a SEPARATE ordered axis** (lane_capability_placement_split.md, 2026-06-09/10). The lane system has two orthogonal axes: **capability/size** (`large`/`medium`/`small`, frozen `_VALID_TIER_NAMES`, assigned by `FunctionRouter` — what the *work* needs) and **placement/origin** (`Origin{LOCAL,CLOUD,PEER}` — *where* it runs). Placement is a first-class TYPE + compile step that **rides on `LLMRouter`'s existing `provider_priority`/`_try_provider` failover — NOT a new resolver** (a second resolver would duplicate `_try_provider` and re-introduce the multi-call hazard the `_MaximPeerBackend` one-HTTP-call invariant exists to kill). The runtime carrier is `LaneConfig.placement: tuple[ProviderPlacement, ...]` ([worker_pool.py](src/maxim/runtime/worker_pool.py)); the declarative twin is `config.json::lanes.<tier>.placement` (`LaneTierPlacement`, [config_loader.py](src/maxim/runtime/config_loader.py)). **Empty `placement == ()` means "derive a 1-element placement from the legacy `model_profile`/`remote_url`/… fields"** — `derive_placement` reproduces the old `_classify` URL-sniff EXACTLY, so existing configs are byte-identical (the `_legacy_classify_oracle` matrix pins this). When `placement` is non-empty it is authoritative; CLI flags edit it on top (CLI > config). Dispatch reads `origin`, not the URL: `_classify = placement_kind(derive_placement(...))`; `_build_backend` dispatches on the primary origin (LOCAL **and CLOUD-profile-without-url** → the profile-driven `_build_local_backend` which `load_llm_config` resolves to the right backend incl. cloud profiles; CLOUD-with-url / PEER → `_build_remote_backend`). Multi-element placements (`local primary → cloud fallback`) compile via **tail-injection** (`_inject_placement_tail` / `_placement_entry_to_provider`) — the primary builds normally, `placement[1:]` append as fallback providers in `provider_priority`; this subsumes `--cloud-fallback`. **Double-injection guard:** the env-driven `_maybe_inject_cloud_fallback` runs ONLY for derived lanes (`cfg.placement == ()`); explicit placements use tail-injection — exactly one path. **Cloud cap:** `MAXIM_MAX_CLOUD_LANES` keys off `placement_kind` = `placement[0].origin` (primary only); a `[LOCAL, CLOUD-fallback]` lane does NOT consume a slot (matches legacy `--cloud-fallback`, gated by `cloud_enabled` + `_validate_cloud_config` instead). Coherence (PEER needs url, LOCAL needs model, CLOUD needs url-or-model) is enforced by `worker_pool.validate_placement_coherence` at the config/CLI producer boundary, NOT in `ProviderPlacement.__post_init__` (the runtime value type stays permissive; derived placements are coherent by construction). `--cloud-lane`/`--cloud-fallback` (+ `MAXIM_CLOUD_LANE_*`/`MAXIM_CLOUD_FALLBACK_MODEL`) are re-expressed as placement edits, kept as deprecated-but-working aliases through 1.x (drop 1.2). Hardware tuning (`n_gpu_layers`/`device`/`n_ctx`/`kv_quant_mode`) stays lane-level on `LaneConfig`, NOT on `ProviderPlacement` (heterogeneous-hardware LOCAL placements are a 1.1+ extension). Regression guard: [tests/unit/test_lane_placement.py](tests/unit/test_lane_placement.py) (`_legacy_classify_oracle` equivalence matrix + explicit-placement dispatch) + [tests/unit/test_lane_placement_config.py](tests/unit/test_lane_placement_config.py) (schema + coherence-at-load) + [tests/unit/test_lane_placement_runtime.py](tests/unit/test_lane_placement_runtime.py) (producer + tail-injection + CLI re-expression).
