**[engineering] Proxy context-overflow admission gate rejects oversize inference requests BEFORE forwarding** (llm_timeout_scalability.md follow-up, 2026-06-04). Pre-gate, prompts exceeding `MAXIM_LLM_N_CTX` caused llama-cpp-server to silently abort generation, producing a stream that limped along with TTFT keepalives until upstream gave up — terrible debugging UX, wasted compute, no actionable error for the agent. The fix lives entirely in the leader proxy: `_proxy_request` reads the request body, gates on `self.path ∈ _PROXY_INFERENCE_PATHS` (`{/v1/chat/completions, /v1/completions}`) AND `_is_admission_enabled()` AND `_get_proxy_context_window() is not None`, then calls `_check_context_admission(body, n_ctx, overhead)`. Rejection returns HTTP 413 with a typed JSON body matching the OpenAI error envelope shape (`error.code`, `error.type`, `error.message`) plus Maxim-specific fields (`estimated_prompt_tokens`, `max_tokens`, `context_window`, `safety_overhead_tokens`) for operator debugging. Token estimation is **character-based** (`len(text) / _PROXY_CHAR_TO_TOKEN_RATIO = 3.5`) — no new dependencies, no extra HTTP round-trip to a tokenizer. The ~10-30% underestimate vs actual tokenizers is covered by `MAXIM_PROXY_CONTEXT_OVERHEAD_TOKENS` (default 256, clamped 0-4096). **Graceful default-on**: gate is ON when `MAXIM_LLM_N_CTX` is resolvable (which it is on any properly-configured leader); OFF with a one-time startup WARNING otherwise. Explicit opt-out via `MAXIM_PROXY_CONTEXT_ADMISSION=0`. Cache for `_get_proxy_context_window()` is a `(resolved: bool, value: int | None)` tuple with `threading.Lock` + a `_reset_proxy_context_window_cache_for_test` helper invoked by the autouse env-scrub fixture in `tests/conftest.py`. **Malformed body bypasses the gate**: `_check_context_admission` returns None on JSON parse failure rather than rejecting — upstream returns a cleaner 400, and we don't false-reject on edge cases the estimator can't handle (vision multipart with non-text parts, custom prompt schemas). **Two-layer defense with `PromptBuilder` + `PromptBudgeter`** ([src/maxim/agents/prompt_builder.py](src/maxim/agents/prompt_builder.py), [src/maxim/agents/prompt_budgeter.py](src/maxim/agents/prompt_budgeter.py)): the agent-side budgeter is the PRIMARY mechanism — it composes prompts within `n_ctx - response_reserve - template_overhead` using priority-tiered section assembly (MANDATORY → CRITICAL → ... → NICE_TO_HAVE; truncatable sections shorten before being dropped entirely). It uses the real `LlamaCppTokenCounter` (precise) when the LLM is loaded, falling back to `CharEstimateCounter` (`len // 3`, deliberately more conservative than the gate's `len / 3.5`) during warmup. The proxy gate is the SECONDARY safety net — it sees the already-budgeted prompt and validates it fits. Both layers read `n_ctx` from the same source (`config.json::llm.n_ctx` / `MAXIM_LLM_N_CTX`), so they cannot disagree on the ceiling. The gate's coarser char-based estimate + 256-token overhead margin is deliberately calibrated so PromptBuilder's accurate-tokenizer output cannot false-trigger it — when the gate DOES fire, it's signal that (a) a non-PromptBuilder client (curl / external script / stress test) sent the request, (b) PromptBuilder was still on its char-estimate fallback during warmup, or (c) `MAXIM_LLM_N_CTX` is misconfigured (operator sets one value, llama-cpp launches at a smaller `-c`). **Both backends always populate `max_tokens` in the outgoing request** — it's a required keyword parameter on `_MaximPeerBackend.complete_with_usage()` and `_OpenAIBackend._complete()`. This means the gate's `_PROXY_DEFAULT_MAX_TOKENS = 2048` fallback is structurally unreachable for Maxim-internal traffic; it only applies to external clients that omit the field (curl probes, ad-hoc API scripts). Regression guard: [tests/unit/test_leader_proxy.py::TestContextOverheadResolver / TestAdmissionEnableGate / TestInputTokenEstimator / TestAdmissionCheck / TestContextWindowResolver / TestBackendsAlwaysSendMaxTokens](tests/unit/test_leader_proxy.py) — 30+ tests pinning env parsing, gate logic, estimator across body shapes, OpenAI-compatible error envelope, cache thread-safety, and the always-send-max_tokens backend invariant.
