**[engineering] Per-tier `lanes.<tier>.timeout_s` flows through `LaneConfig.remote_timeout_s` → provider config without backend wiring changes** (llm_timeout_scalability.md Stage 2, 2026-06-04). The schema field lives on `LaneTierConfig` (CC3 path-a, declared field with `__post_init__` validation: strictly positive, numeric). The env-var family `MAXIM_LANE_<TIER>_TIMEOUT_S` is registered in `_FIELD_TO_ENV` with a float coercer (`_coerce_for_field` in `runtime/config_loader.py`) that enforces the same > 0 invariant at the loader layer. `_apply_lane_config_to_env` populates the env var from `config.json` when source is non-default; `apply_lane_env_overrides` (in `runtime/lane_models.py`) reads the env var into `LaneConfig.remote_timeout_s` with a defensive silent-ignore on malformed or non-positive values (the loader-side raises `ConfigurationError`; this path is the bypass-the-loader belt-and-suspenders). The lane backend manager at `runtime/lane_backends.py` threads `cfg.remote_timeout_s` into `providers[provider_key]["timeout_s"]` only when the value is non-None — both backends (`_MaximPeerBackend._get_timeout_policy()` and `_OpenAIBackend._get_timeout()`) already read `_provider_cfg().get("timeout_s", <default>)` per the Plan 3 R2.5 contract; populating the key is sufficient. **Do NOT change either backend's default value to honor a missing config**: 300s for self-hosted, 60s for cloud is the right pair, and config absence means "use the backend default" — not "use 0". Regression guard: [tests/unit/test_config_loader.py::TestLaneTierTimeoutField](tests/unit/test_config_loader.py) (13 tests pinning field validation, JSON parser, env coercion, resolve_setting precedence) + [tests/unit/test_leader_proxy.py::TestLaneTimeoutFieldFlow](tests/unit/test_leader_proxy.py) (4 tests pinning env passthrough into LaneConfig.remote_timeout_s).
