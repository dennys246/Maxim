**[behavioral] Running-mean centroid drift in cosine-similarity pattern completion** (EC centroid drift fix, five-phase plan `docs/plans/archive/ec_centroid_drift_fix.md`, 2026-05-23 / 2026-05-24): the pre-fix `EntorhinalCortex.pattern_complete_or_separate` updated each matched node's centroid as a running mean of all admitted embeddings. With threshold 0.40 on the `"text"` modality, successive marginally-above-threshold matches (cosines 0.42-0.48) pulled the centroid toward a generic "second-person body sensation" prototype that then pattern-completed everything subsequent. The diagnostic ([24_roy_paraphrase_diagnostic.md](docs/experiments/24_roy_paraphrase_diagnostic.md)) showed 19 of 20 unique paraphrase strings collapsing into ONE EC node under sequential streaming, while the SAME pairs in isolation (fresh EC per pair) clustered perfectly (10/10). The asymmetry between isolated and sequential measurement is the diagnostic signature of progressive centroid drift. **Detection rule:** when validating a new EC modality or substrate-encoding path, ALWAYS measure both isolated (fresh EC per item) and sequential (one EC, all items) — if they disagree sharply, drift is the culprit. **Fix rule:** for any modality where downstream concepts must persist as distinct clusters across a session, choose either (a) frozen-prototype semantics — add the modality to `ECConfig.frozen_centroid_modalities` (this is the existing fix for `"interoception"`), or (b) raise `pattern_complete_threshold` enough to reject the marginal admissions that cause drift. The Phase 1/2 matrix sweep showed (b) is the right lever for `"text"` (threshold 0.40 → 0.44 — 0.05 grid sample missed the sweet spot, 0.01 fine sweep named it). (a) hurt P1 paraphrase recall too much for text. **Sampling-granularity rule for parameter sweeps on precision-recall trade-offs:** default to 0.05 granularity (matches the original P1 P2 tuning precedent); drop to 0.01 only when the 0.05 result sits at a regression boundary — N passes, N+1 fails, both within noise of a downstream gate. Don't drop to 0.01 by default. **NAc threshold-override coupling (Phase 3.5):** `NAc.get_threshold_overrides(agent_id, *, base_threshold=None)` accepts the live EC threshold from the caller. Production callers (`LinguisticEncoder._get_reward_overrides` + `encode_decomposed`) MUST pass `self.ec.config.pattern_complete_threshold` so the override tracks whatever threshold the matching EC instance is using. The `None` fallback is hardcoded to 0.44 for legacy callers that lack an EC reference (three unit-test sites); the fallback's value is pinned to the EC default by `test_nac_threshold_override_base_tracks_ec_default`. At non-default EC thresholds (e.g., P2's 0.70), the pre-Phase-3.5 hardcoded base accidentally widened recognition by `(base - 0.44) + bias` cosine units instead of the bio-correct `bias`-magnitude widening — invisible at the production default, load-bearing at any non-default threshold. **Behavioral validation on Roy-2c (Phase 4):** drift was REAL (six spurious priming UUIDs per concept collapsed to one — cluster_reward_bias_l2 dropped 79%) but drift is NOT the dominant Roy persona-inertness mechanism (behavioral signal unchanged — the H1 cross-source alignment gap between priming-substrate text and CLI-fixture text is structurally upstream of drift). Fix ships as substrate hygiene + V1 cross-session prerequisite; JEPA / cross-modal binding stays a 1.0-or-1.1 gate.
