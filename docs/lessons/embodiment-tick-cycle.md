- **[engineering] Embodiment tick cycle lives in `Body.evaluate_failures()`, not percepts.py** (corrected 2026-07-14; the previous inverted text went stale within hours of being written — `ed8b187f`, 2026-04-26, moved the tick INTO `evaluate_failures` because nothing constructed `EmbodimentPerceptSource` and drives were frozen). `evaluate_failures()` applies `tick_vital_drift` automatically using wall-clock dt (`now - _last_poll`; first call sets the baseline, no drift), so drives advance on every path that touches the body — affordance execution ([embodiment/tool_bridge.py](src/maxim/embodiment/tool_bridge.py)), sim tools ([simulation/tools.py](src/maxim/simulation/tools.py)), and the substrate-primary per-proposal tick ([runtime/agent_loop.py::propose_via_substrate](src/maxim/runtime/agent_loop.py)) — including during LLM latency (elapsed time is applied lazily at the next call; multiple calls per turn cannot double-drift because dt is elapsed wall time). **Do NOT add a second `tick_vital_drift` call site** — `ed8b187f` removed the percepts.py duplicate specifically to prevent double-drift. (Adding another `evaluate_failures()` *caller* is safe — it is idempotent w.r.t. elapsed wall time; the invariant is specifically about not adding a raw `tick_vital_drift(` site.) On the LLM-primary path the tick now fires **per live loop iteration** via [`runtime/agent_loop.py::tick_embodiment_drift`](src/maxim/runtime/agent_loop.py) (Track 1 of `embodiment_runtime_wiring.md`, 2026-07-17) — placed after the pause check and before the 0.6 idle gate so a *sitting* Reachy body still drifts (cold/hungry) through pure-thinking turns, idle gates, and LLM latency; it was previously **event-driven only** (fired on tool execution), which froze the body on any turn without a tool call. The helper is a **no-op on substrate-primary** (that path ticks itself in `propose_via_substrate` — a second tick would double it) and when unembodied. Because drift is elapsed-wall-clock, the per-iteration tick + a later tool-driven `evaluate_failures()` in the same iteration cannot double-drift (dt≈0 on the second call), and total time-based depletion is unchanged — only pain-evaluation granularity gets finer. Substrate-primary still ticks per proposal. **Cadence caveat (RESOLVED 2026-07-28; originally three-lens impl review [reviews/track1_impl_three_lens_review.md](docs/plans/reviews/track1_impl_three_lens_review.md) F2):** the per-iteration cadence originally made state-based drive-pain re-publish per call — the exact revival trigger `deferred/transition_based_drive_pain.md` named. The severity latch (drive-pain invariant above) now gates the PainBus channel on band entry + material re-injury, so finer tick granularity no longer multiplies *pain publishes*; the direct `FailureEvent` channel remains per-call by design (B8 filters it). **Exp 44 embodied llm-primary numbers still need re-validation against the Track-1 cadence** (drift *timing* changed even though pain emission is now transition-clean). `embodiment/percepts.py::EmbodimentPerceptSource` was NEVER production-wired (pickaxe-verified: its constructor never entered `src/` in any commit) and is Dormant — kept as the CC8 `PerceptSource` protocol-shape template for the 1.1 remote-percept adapter (class exercised by [tests/unit/test_producer_protocols.py](tests/unit/test_producer_protocols.py) + [tests/unit/test_naming_events.py](tests/unit/test_naming_events.py); the Protocol itself is pinned by [tests/unit/test_percept_source_protocol.py](tests/unit/test_percept_source_protocol.py)). Known gap (partly closed 2026-07-17; default still OFF, pre-registration at [docs/plans/deferred/acting_coach_body_state_ablation.md](docs/plans/deferred/acting_coach_body_state_ablation.md)): `memory_hub.embodiment` is wired at TWO gated production sites — the Exp 44 seam `agent_factory._maybe_wire_body_state` AND (Track 1 Layer 3a) the Reachy runtime `agentic_runtime._start_agentic_runtime` — both behind `body_state_prompt_enabled()` (`MAXIM_ENABLE_BODY_STATE_PROMPT`, default OFF), so `format_body_state_for_prompt` → `StructuredContext.body_state` populates only when the flag is set (and, on the Reachy path, only when a body is declared via `robots.yaml::config.body`).
