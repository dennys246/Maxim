- **[engineering] Drive-pain emission is CHANNEL-SPLIT: the direct `FailureEvent` channel stays state-based; the PainBus channel is severity-latched (fires on band entry and on material re-injury), latched on the ENTITY** (transition_based_drive_pain.md Phases 0-1 + the pre-merge two-lens fold, 2026-07-28). The two attribution channels need different emission semantics and conflating them is what the fold caught:
  - **Channel 1 — the `FailureEvent` list returned by `Body.evaluate_failures`** (→ `ToolOutput.side_effects["embodiment_failures"]` → `ToolPainBridge.record_tool_embodiment_failure`): **state-based, one event per call while breached — do NOT latch it.** B8 delta-attribution already filters this channel correctly and, critically, is **state-independent**, so it keeps separating causer from bystander even at sensor saturation where a severity latch is blind. Latching here silently starves B8 and inverts a repeat harmful affordance to POSITIVE credit (see the B8 SCOPE note above).
  - **Channel 2 — `_publish_drive_pain`** (→ PainBus → `create_pain_nac_subscriber`, hippocampus episodic capture, Wire-2 valence, `PainCircuitBridge`, and the SCN `TemporalEvent`): **severity-latched.** Fires on band entry, and again only when the breach deepens by more than `_BREACH_DEEPEN_FRACTION` of the spec's own band/threshold gap (floored at `_BREACH_MIN_EPS`) — so per-tick drift creep is silent but genuine re-injury is heard. This is the bio-faithful shape: repeated noxious stimulation of already-injured tissue **sensitizes**; it does not go silent. Recovery uses **hysteresis** — homeostatic clears only inside `comfort_band * (1 - _BREACH_HYSTERESIS)`, entropic clears at the spec's own `satisfaction_threshold` — so a noisy world-set sensor sitting on the band edge (live DoA azimuth is exactly this) cannot chatter one "onset" per jitter.
  - **The latch lives on `Entity.drive_breach_severity`, not on the `Embodiment` wrapper** (`__slots__`-declared, never serialized — `to_dict`/`from_dict` omit it, mirroring `FailureMode.active`). A body must not forget it is injured because a different observer looked at it: `simulation/tools.py` constructs ephemeral per-invocation `Embodiment` wrappers over the same entity. Entity-owned state also means reparenting (entity acquisition changes `full_path`) does not spuriously re-fire, same-named siblings cannot collide, and detached entities cannot leak keys — all failure modes of the path-keyed first draft.
  - **Unreadable sensor clears the latch** (`readings.get(name) is None`): "unknown" is treated as "not breached", because retaining the latch would silently swallow the next genuine breach when the sensor returns out of band.
  - **Motivation is untouched by both channels** — it rides the drive VALUE (`body_state_summary` / `_read_drive_states` / acting-coach), verified consumer-by-consumer. Standard (non-drive) `failure_mode`s keep their own per-call trigger semantics. **Note the opposite latch polarities:** `FailureMode.persistent` means "keep firing until recovery"; `drive_breach_severity` means "stay quiet unless the injury deepens". Declaring `persistent: true` on a drive does nothing — drives are not `FailureMode`s.
  - **SCN oscillator consumer — CONCERN VOID, and a real wiring gap found instead (2026-07-29).** The fold's drive-`TemporalEvent` density was flagged as a possible regression against `OscillatorNetwork`'s `< 3 observations` cold-start guard. Measuring it on a real run showed the premise was false: **no drive `TemporalEvent` has EVER reached the SCN oscillator, in any production run, before or after this change.** `Body._emit_drive_temporal_event` early-returns on `self._distributor is None`, and the canonical builder never supplies one — `runtime/bootstrap.py::build_executor` threads its `distributor=` argument into `ToolPainBridge` (`:439`) but constructs `Embodiment(entity, pain_bus=..., agent_id=...)` without it (`:456`). Verified empirically: a proper substrate-primary cradle run persists `aut_scn.json` with 10 event signatures and **zero** `drive:*` ones. So the fold cannot have changed drive-phase density, and `anticipatory_pre_activate` has never had drive events to work with. **Do NOT opportunistically wire `distributor=` into that `Embodiment` construction** — and note the wire ALONE would not work: the `TemporalEvent(...)` call in `_emit_drive_temporal_event` is *also* malformed (passes `temporal_signature=`/`metadata=`, which are not fields — they are `temporal_sig`/`context` — and omits the required `event_id`/`event_signature`), so it raises `TypeError` into a `except Exception: log.debug(...)` swallow. Wiring the distributor would convert a silent early-return into a silent `TypeError`: the path would *look* connected and still emit nothing. Both must be fixed together or neither. A wider audit (2026-07-29) found this is not isolated — of the six `event_type` categories `TemporalEvent` declares (`tool`/`pain`/`reaction`/`percept`/`affordance`/`deliberation`), **only `tool` has any producer** (12, all in `ToolPainBridge`); `record_event` even special-cases `deliberation` significance for a producer that does not exist. So the oscillator's circadian learning — and `anticipatory_pre_activate` — runs on one input channel of six. Full write-up + revival criteria: [docs/plans/deferred/scn_event_producer_gap.md](docs/plans/deferred/scn_event_producer_gap.md). Fixing any of it activates a never-run learning path and needs its own validation; the prior question is whether per-event-type phase learning earns its keep at all (B2 is `[engineering]`-tier, never behaviourally graduated).
  - **Behaviourally validated (2026-07-29): GRADUATE #6 HOLDS.** Exp 42 triage re-run, 40 sub-sims (10 seeds/arm × 2 counterbalanced arms × gating ON/OFF), 0 failed, 0 floored: H1 0.996/1.000, C1 +0.996, C2 PASS in both configurations, `harm_net = -0.25` every seed (so the near-ceiling `safe_pref` is real discrimination, not absence of contact). Post-fold is **identical** to the pre-fold main baseline — the predicted result, since Exp 42's discrimination rides the direct channel this split deliberately left state-based; a difference here would have meant the split leaked. **Caveat:** `safe_pref` is saturated (SD 0.000 across pre-fold / post-fold / gating-ON / gating-OFF), so this supports "did not break discrimination" but cannot detect a moderate regression — a future degradation arm needs a more sensitive statistic.
