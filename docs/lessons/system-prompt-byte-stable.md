- **[engineering] The system prompt MUST be byte-stable across turns within a session** (prompt-caching prerequisite, prompt_caching_for_cloud_backends.md, 2026-06-08). `PromptBuilder.build_prompt` emits `TOOL_PROMPT|<stable_prefix>\x1e<dynamic_remainder>` (delimiter `PROMPT_SEGMENT_DELIMITER`); `LLMRouter._generate_tool_response` routes the stable prefix into the `system` message (appended after `SYSTEM_TOOL_RESPONSE`, so the whole system block ends at the cloud backends' `cache_control` breakpoint) and the dynamic remainder into the `user` message. A section is in the stable prefix iff it calls `budgeter.add(..., cacheable=True)` — reserved for genuinely session/phase-stable content (identity, instructions, tool guidance, foundational, entity_context, tools[phase-scoped]). **Any byte change in the stable prefix between turns invalidates the cache and re-spends ITPM on the full prefix**, so per-turn-dynamic content (drive states/`body_state`, datetime, memories, bio annotations like Wire-A/W1, observations, conversation) MUST NOT be tagged cacheable — it belongs in the dynamic remainder. `PromptBudgeter.build_segmented()` budgets the stable sections first, independent of dynamic content (capped at `_STABLE_BUDGET_FRACTION`=0.7 of budget), so truncation of dynamic sections cannot perturb the prefix. `prompt_cache: true` on a profile (Anthropic: real `cache_control` marker; OpenAI: gates the `openai_cache` measurement event, caching is automatic server-side) flows profile → `LLMConfig.prompt_cache` → synthesized provider entry / backend `_prompt_cache_enabled()` fallback. When adding a new prompt section, default to dynamic (no `cacheable=`); only tag `cacheable=True` after confirming it cannot vary within a session. Measured win on cradle/Sonnet: ~38% ITPM reduction (the prefix is the small stable fraction, NOT a 6× win — see plan Results).
