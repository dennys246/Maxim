- **[engineering] `runtime/role.py::detect_role` is the single source of truth for role detection** (config_unification.md C3, 2026-06-02, PR pending). The pre-C3 two-detector architecture (this module + `runtime/leader_mode.py`) was split because they grew from different motivating cases. Both ran at startup and could silently disagree. The 2026-06-01 Mac Mini regression hit divergence on day one. **Post-C3 the seven-rank decision order lives in `role.py::detect_role`**: (1) `MAXIM_ROLE` env var; (2) `config.json::role` (NEW per C3); (3) `mesh.yml` exists → peer; (4) `~/.cloudflared/config.{yml,yaml}` exists → leader (MOVED UP from `leader_mode.py` + extension widened to fix Mac Mini Trigger #2); (5) `peer.yml` exists → peer (DEMOTED below cloudflared — fixes Trigger #3, the stale-peer.yml-on-now-leader case); (6) `--llm <local>` CLI flag + no peer/mesh/cloudflared → solo; (7) default → leader. `runtime/leader_mode.py::detect_role` is a thin wrapper that translates `Role` → `RoleDecision(role, bind_host, reason)`, returns the legacy `client` term for what `role.py` calls `peer` (back-compat through 1.x, drops in 1.2). The `role_divergence` event continues firing at DEBUG with `data={"deprecated": true, "reason": "single detector (C3)"}` for one minor (N-2 fold), drops entirely in 1.2 so external dashboards don't silently lose a column. `_config_json_role()` surfaces `ConfigurationError` as a WARNING (post-implementation Executor I3 fold) so a typo in config.json doesn't silently corrupt rank ordering. Regression guard: [tests/unit/test_role_unification.py](tests/unit/test_role_unification.py) (the eight-cell matrix pinning every Mac Mini failure mode + the ConfigurationError surface) + [tests/unit/test_role_detection.py](tests/unit/test_role_detection.py) (the legacy seven-rank tests updated for C3 ordering) + [tests/unit/test_leader_mode.py](tests/unit/test_leader_mode.py) (wrapper translation contract).
