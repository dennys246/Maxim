- **[engineering] `_maybe_migrate_from_peer_yml` auto-migration writes peer.yml → config.json on first startup** (config_unification.md C4 IM5 fold, 2026-06-02, PR pending). Triggers iff config.json is absent + peer.yml is present + cloudflared config is absent. The cloudflared absent condition preserves the legitimate leader-with-stale-peer.yml case (Mac Mini Trigger #3) — a leader machine must never have its role auto-flipped to peer just because an old peer.yml lingers. Writes `config.json::role=peer` + `lanes.large.{remote_url, remote_model, remote_api_key_ref}` populated from peer.yml fields. peer.yml is NEVER deleted by the shim. The API key is written to `~/.config/maxim/api_key` via `atomic_write_secret` inside a tightened `umask(0o077)` window (post-implementation Executor C3 fold closes the umask race) + explicit `chmod(0o600)`; config.json stores the file-path reference. Module-level `_migration_attempted` flag prevents repeat work but is set AFTER successful write (post-implementation Executor I2 fold) so a transient OSError (permission denied, disk full) can recover on the next `load_config()` call. **Self-hosted classification preservation:** when `lanes.<tier>.remote_url` resolves via env or config (not cloud config), `runtime/lane_backends.classify_self_hosted_lane` sets `MAXIM_MAX_CLOUD_LANES=1` so the cloud-lane gate doesn't refuse self-hosted peer URLs. Cloud-provider opt-in stays explicit via `config.json::cloud.enabled = true`. **`_apply_lane_config_to_env` is idempotent** (post-implementation Executor C1 fold) via `_lane_env_applied` flag — without the guard, a second call sees env vars set by the first call and re-attributes the source from "config" to "env", silently breaking C5's doctor source attribution. Tests reset via `_reset_lane_env_applied` in the autouse `_isolate_config_json_env` fixture. **peer.yml fallback compat-read** in `_apply_lane_config_to_env` handles the cloudflared-present case (migration skipped); replicates the env-population pattern in-function rather than routing through the legacy `apply_peer_config_to_env` shim (post-implementation Executor C2 fold). Regression guard: [tests/unit/test_lane_routing_via_config.py](tests/unit/test_lane_routing_via_config.py) (migration shim + idempotency + retry-on-transient-failure + self-hosted classification + peer.yml fallback).
