- **[engineering] Substrate-primary action selection is credited by the SIGN of drive VALUE-PROGRESS toward comfort (`drive_potential_diff`), not tool-execution success** (orient motor-credit; value-progress fix after the #405 Exp-42 floor, 2026-07-20). The `±1` tool-success signal is direction-blind — it rewards `turn_left` whether it turns toward OR away from a sound, so an orienting agent learns only "turning succeeds," never "turn *toward* the sound." `ModulatorAffordanceTool.execute` emits `side_effects["drive_potential_diff"]` = `Σ drive_comfort_progress(spec, before, after)` over the entity-level drive sensors its **own `self_effect`** touched (`target_effect` is NOT scored — caregiver relief is the other body's state, not the actor's policy). `drive_comfort_progress` ([embodiment/sem.py](src/maxim/embodiment/sem.py)) is **value-based, NOT pain-based**: homeostatic = reduction in `|value − set_point|`; entropic = value moved toward comfort per drift direction. This is load-bearing — `drive_pain_for_value` is a STEP function for entropic drives (`deprivation_pain` past threshold, `0` below), so a **pain-based** reward books ZERO relief for a warm/feed that reduces cold/hunger *without crossing* the threshold, starving entropic-relief actions (warmth, feeding) of credit so the agent abandons them (the #405 regression: Exp 42 floored 60→8 warmth contacts, safe_pref 0.98→VOID; the orient probe missed it because its action space was all-homeostatic-turns with no `+1` non-drive competitor). `record_outcome` (`runtime/tool_dispatch.py`) takes the **SIGN** (`+1` progress / `−1` regress), NOT the magnitude — so drive-relief actions sit on the same `±1` scale as the tool-success non-drive actions get (a small graded magnitude, e.g. one warm step ~0.2 or an azimuth step 0.3, would lose the argmax to a flat `+1`); exactly-`0` net progress → tool-success fallback. `drive_pain_for_value` stays the single source of truth for the failure/pain formula (`evaluate_failures`), distinct from the reward. **Collateral-harm gate:** the producer suppresses the signal to `None` when the action caused a failure on a sensor its progress did NOT account for (a non-drive `failure_mode` like `arms.thermal`, or an untouched drive) — so an attractive-but-harmful action (relieves `cold`, breaches `arms.thermal`) cannot be credited positive, which would defeat the Exp 42 safe-vs-harm discrimination. A **same-sensor** drive discomfort (azimuth still off-center after a relieving turn) is NOT collateral. The harm decision lives in the PRODUCER (where the failure sensors are visible), NOT the consumer; a `not embodiment_failed` gate at the consumer would break orient.
