# Frozen dataclasses shipping in 1.0 are forward-compat-audited

**Archived from CLAUDE.md on 2026-08-13** (claude_md_diet Stage 1). The enforced rule
survives as a compressed stub — in the slim CLAUDE.md core or in the owning

---

- **[engineering] Frozen dataclasses shipping in 1.0 are forward-compat-audited** (CC3, 2026-04-28). Every `@dataclass(frozen=True)` shipping in 1.0 must declare in its class docstring which of two paths it takes — picking is mandatory before merge for any new frozen dataclass:
  - **(a) Escape-hatch dataclass** — all fields have sensible defaults *and* an `extra: dict[str, Any] = field(default_factory=dict, hash=False, compare=False)` field. The `hash=False, compare=False` is load-bearing: a `dict` field on a `frozen=True` dataclass otherwise breaks `__hash__` and inflates `__eq__` with mutable observability data. `extra` values **must be JSON-serializable** (str/int/float/bool/None + nested list/dict only) — `numpy.ndarray`/`datetime`/objects raise at persistence time. Producers prefer declared fields; `extra` is for genuinely additive metadata only. **The dataclass `__post_init__` must reject extra keys that collide with declared field names** (per the post-implementation Architecture #4 fold for `LaneTierConfig` — the constructor's collision check pushes the invariant into the type so a malformed dataclass cannot reach the writer). Current: `Episode`, `SensorReading`, `LaneTierConfig`, `ProviderPlacement`, `LaneTierPlacement`.
  - **(b) Shape-frozen dataclass** — the docstring carries an explicit `SHAPE-FROZEN at 1.0 (CC3)` marker explaining why an `extra` hatch was rejected (typed contract that an `extra` dict would dilute, isolation-hygiene rule that an `extra` dict would re-open, parser-frozen wire format, etc.). Adding a *required* field post-1.0 is a major-version-bump change. Adding an optional field at the end with a default is non-breaking but still requires the review gate the docstring describes. Current: `Reaction`, `ReactionContext`, `TraceSnapshot`, `PerceptContext`, `CouplingSpec`, `ModulationSpec`, `HomeostaticDriveSpec`, `EntropicDriveSpec`, `TemporalSignature`, `ValenceSignal`, `MeshNode`, `MeshConfig`, `ModelPricing`, `VRAMProjection`, `MaximConfig`, `LLMConfigSection`, `LanesConfigSection`, `CloudConfigSection`, `ProxyConfigSection`, `AutoSpawnConfigSection`, `DataConfigSection`, `SimConfigSection`. (`TraceSnapshot` is shape-frozen because it's reachable from `ReactionContext.bindings` — an `extra` dict on it would re-open the same isolation back-channel `ReactionContext` itself closes.)
  - **Typed exception hierarchies** (`models/language/types.py::BackendError`, `utils/http.py::HTTPError`) follow the same spirit but different mechanics: they are not dataclasses, they have explicit keyword-only `__init__` signatures per subclass. Adding `**kwargs`/`extra` re-opens the silent-typo class of bugs that `BackendError` Fix #8 closed (e.g., `retry_after=2.5` instead of `retry_after_s=2.5`). New keyword-only parameters with defaults may be added per subclass; new subclasses require the matching `_classify_status` / `_try_provider` branch in specific-before-general order.
  - **Out of scope for the audit:** runtime-ephemeral configuration dataclasses (`HippocampusConfig`, `RetrievalConfig`, `NACConfig`, ...) that never cross a wire or a session boundary. Adding fields with defaults at the end is the standard non-breaking path. Persisted *and* wire-crossing types are the audit surface.
  - **Regression guard:** CC3 audit list + the `SHAPE-FROZEN at 1.0 (CC3)` docstring marker on each frozen-without-extra dataclass; new frozen dataclasses must pick path (a) or (b) before merge.
