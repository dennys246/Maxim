# Configure model + n_ctx via maxim config — the n_ctx drift bug (three legs)

**Archived from CLAUDE.md on 2026-08-13** (claude_md_diet Stage 1). The enforced rule
survives as a compressed stub — in the slim CLAUDE.md core or in the owning
`docs/agents/<subsystem>.md` brief (see CLAUDE.md's routing table). This file preserves

---

- **Configure model + n_ctx via `maxim config`, not transient env/flags — single source of truth.** Set `maxim config set llm.profile <profile>` and `maxim config set llm.n_ctx <N>` (persisted to `config.json`), then VERIFY with `maxim doctor 2>/dev/null | grep -i "n_ctx\|profile"` before a real run. **Why (2026-07-15 Exp 44 blocker):** the LLM server's spawn n_ctx and the PromptBudgeter's n_ctx belief are resolved through DIFFERENT paths — the server reads `MAXIM_LLM_N_CTX`/spawn precedence (`lane_backends.py:2474`) while the AUT budgeter reads `router.n_ctx` = `router.cfg.n_ctx` = the *profile default* (`router.py:203`; e.g. qwen2.5-32b's 32768). If they drift, the budgeter composes a prompt larger than the server's context → llama-cpp returns a raw **HTTP 500** (`down_500`), the provider cools down, and every subsequent call is `_llm_unavailable` → the agent silently takes 0 real actions. A one-shot `MAXIM_LLM_N_CTX=16384 maxim --llm <model>` sets the SERVER but NOT the budgeter (which reads the profile) — the two must agree, and `config.json` is the way to make them. Sub-sims inherit `config.json` via `_apply_lane_config_to_env`, so persisting there fixes the whole process tree. **Known bug (PARTLY FIXED 2026-08-07, 1.1 item 3 — three legs, one closed, one subsumed, one open):** (leg 1, FIXED) the `llm_worker.py` clamp — the worker now clamps its budget to the *smallest declared positive* provider context (`min`, lower-only, no cloud gate, narrowed except incl. `AttributeError`, nonpositive declarations skipped as malformed since with `min()` a bogus `-5` would poison the whole budget; guard: [tests/unit/test_llm_worker_n_ctx_clamp.py](tests/unit/test_llm_worker_n_ctx_clamp.py), verified to fail 4/7 pre-fix). (leg 2, SUBSUMED but latent) `router.n_ctx` itself still returns the raw profile default — today every LLMWorker construction site passes `n_ctx=router.n_ctx` (api.py:450 was the one site that passed NOTHING, riding the old cloud max()-raise for its budget; fixed in the same fold to follow the console/handle.py pattern), so the worker clamp covers them all — but a future DIRECT consumer of `router.n_ctx` re-inherits the bug; the property is unclamped. ACCEPTED TRADE: with a min() budget, the router's `context_window_routing` can no longer route a long-context burst to a bigger cloud fallback in a mixed lane (that window is unreachable by construction) — one conservative budget for all providers is the 1.1 semantics; per-provider budgets belong with leg 3. Do NOT re-add max() to "restore cloud routing". (leg 3, PARTIALLY CLOSED 2026-08-09) auto-spawn now stamps `LaneConfig.served_n_ctx` — the context the server was ACTUALLY launched with — on the fresh-spawn and owned-server-reuse rewrites, and `_build_remote_backend` declares it on the lane provider entry + the lane llm_config's `n_ctx`, so both the worker clamp and `router.n_ctx` track the real served window from first spawn (this also supersedes leg 2's "raw profile default" wording for auto-spawn lanes). NOTE the pre-fold text's "update_provider_n_ctx on hot-swap" claim was itself overstated: that call targets provider key `"local"`, a silent no-op on lane routers whose key is `"lane-<tier>"` — the swap loop now also refreshes every provider entry pointing at the swapped server. **What remains OPEN: cross-process reuse.** A sub-sim in a different process reusing the leader's server sees `_active_spawner is None` (per-process global) → no stamp → profile-default budgeting — exactly the Exp 44 harness topology. So the `maxim config` alignment remains mandatory for harness/sub-sim runs and externally-started servers; single-process auto-spawn runs are now self-aligning. Guard: [tests/unit/test_lane_served_nctx.py](tests/unit/test_lane_served_nctx.py) (verified to fail pre-fix); `served_n_ctx` is visible in `lane_decisions.jsonl` for drift auditing. **Never co-locate a `maxim-leader`/experiment run with the sim on one box** (the Exp 37 cradle-cascade lesson) — a second consumer of the :8100 server causes 500s under contention independent of n_ctx.
- **IMPORTANT: Use `--interactive false` when running sims from Claude Code or scripts.** Interactive mode is ON by default in CLI with a TTY (0.3.2). The raw terminal reader conflicts with non-human stdin. Always pass `--interactive false` for automated/scripted sim runs.
- **Set a narrow goal.** `--goal "test X specifically"` beats `--goal "test safety"` — specific goals converge faster.
- **Cap duration.** Hit Ctrl+C after 30–90 seconds when you've seen what you need. Sims report partial results on cancel.
- **Prefer --sandbox tmpdir for debugging** unless you're specifically testing Docker — tmpdir has no pull/startup cost.
- **Use --debug sparingly.** The verbose-trace output is great for diagnosing stalls but floods the terminal for routine runs.
- **Don't invoke sims from test suites** unless the test is specifically for sim machinery. The sim runner spins up real LLM calls and can 2-3x test-suite runtime.
- **Re-use sessions with --resume-sim SESSION_ID** to avoid re-running setup + warm-up costs when iterating on a specific run.
- **Local models > Claude for loop-testing.** Use `--language-model mistral-7b` for sanity checks; save Claude for verifying final behavior.
- **Watch for Cost:** in the final report. $0.05–$0.15 per short run is normal; $0.50+ for a single debug session suggests the sim is too broad or too long.
