**[engineering] An experiment harness MUST assert that the `maxim` its sub-sims import is its OWN repo — `git_hash` answers the wrong question** (Exp 42b invalidation, 2026-07-28). A 40-sub-sim behavioural re-validation had to be **retracted** because its provenance could not be established. `maxim` is a console script resolving `import maxim` purely through `sys.path`; a venv can carry stale editable `.pth` files from an old `pip install -e` pointing at other checkouts or deleted worktrees. `PYTHONPATH=<repo>/src` does beat a plain `.pth` (setuptools emits a path-append `.pth`, not a PEP-660 `__editable___*_finder` MetaPathFinder — **if that ever changes, the finder would sit in `sys.meta_path` and beat PYTHONPATH, so this win is a property of the current install strategy, not a guarantee**) — but only when it is actually set AND resolvable. Three silent failure modes conspired: (1) `PYTHONPATH=src` is **relative**, so it evaporates unless the launch cwd is the repo root; (2) the launching shell ran `source .venv/bin/activate && export PYTHONPATH=src` where the `source` FAILED, so `&&` short-circuited and **the export never happened**, with no error; (3) `_git_hash()` in every harness runs `git rev-parse` in the **harness file's** directory, so the recorded hash describes where the harness LIVES, never which code the sub-sims IMPORTED — it stamped the right hash onto runs of the wrong code. Every sub-sim "succeeded"; the JSONL looked authoritative; the mistake surfaced days later only via an unrelated missing-artifact symptom, by which point it was unfalsifiable in either direction. **Rule:** any harness that spawns `maxim` calls `scripts/_provenance.py::assert_repo_interpreter(repo_root, binary, exempt=<mock>)` before its first sub-sim (exit 3 on mismatch), and SHOULD stamp `executed_code_provenance(...)` — `executed_maxim_file` / `executed_git_hash` / `pythonpath` alongside `harness_git_hash` — into every run record so the artifact is self-auditing after the shell history is gone. The probe runs through the console script's OWN shebang interpreter with the sub-sims' env, because probing in-process would test the harness's interpreter, which need not be the one `maxim` runs under. **Corollary — the standard this enforces:** a result whose code-under-test cannot be established is not a validation, independent of whether it happens to be correct; do not argue it was "probably fine". **Operator hygiene:** always `export PYTHONPATH="$PWD/src"` (absolute) on its OWN line, never chained after a `source` with `&&`; give each worktree its own venv + editable install so PYTHONPATH is never load-bearing; and periodically audit site-packages for orphaned `__editable__*.pth`. Regression guard: [scripts/lint_harness_provenance.py](scripts/lint_harness_provenance.py) in CI (shipped 2026-08-13) — every `scripts/**/*.py` matching a spawn-of-maxim pattern must reference `assert_repo_interpreter` or carry a `# provenance-exempt: <reason>` marker; as of the ship date all six spawning harnesses (`benchmark_exp42_preference.py`, `benchmark_exp41_exploration.py`, `benchmark_cross_session.py`, `benchmark_cradle_mother.py`, `exp44/campaign.py`, `exp49/run_trials.py`) call it — plus [scripts/_provenance.py](scripts/_provenance.py) itself and the post-mortem in [docs/experiments/42b_drive_pain_fold_revalidation.md](docs/experiments/42b_drive_pain_fold_revalidation.md).
