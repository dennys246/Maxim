**[engineering] Per-agent stash dicts (not module-level globals) for multi-agent state** (v1 P4, 2026-04-28): The pre-fix `runtime/bio_integration.py` carried module-level globals `_episode_tick`, `_latest_pain_intensity`, and `_latest_substrate_nodes` with a docstring comment that read "acceptable because multi-agent substrate encoding is not yet a production path. If it becomes one, scope per agent_id." Three failure modes hidden behind that caveat: (1) a *single* tick counter ordered events across all agents instead of per-agent; (2) substrate nodes encoded for agent A on the producer side (`MemoryHub.on_percept_received`) could land on agent B's next `observe_episode` event because the consumer (`agent_loop.observe_episode`) read the same stash slot; (3) max-merging pain intensities silently dropped agent A's pain when agent B happened to be louder in the same tick. **Rule:** any per-agent runtime stash MUST be a `dict[agent_id, value]` from day one, with `agent_id: str` as a required keyword-only parameter on every entry point that reads or writes it. The value type is whatever the slot held before. Empty-string `agent_id` is rejected by a `_check_agent_id` validator at every entry — without it, `agent_id=""` silently merges every "agent" through one shared key and re-introduces the original collision class. **Producer-consumer key alignment is load-bearing:** when a producer (`MemoryHub.on_percept_received`) and a consumer (`agent_loop.observe_episode`) sit on opposite ends of the stash, they MUST agree on the key. P4 picks a single canonical key — `memory_hub.agent_id` (set at `build_memory_hub`/`build_bio_stack`/`AgentFactory.create_agent`) — and the consumer derives `_loop_agent_id = memory_hub.agent_id or _safe_agent_name(agent)` so both ends use the same string. The fallback to `_safe_agent_name(agent)` is for raw-loop callers without a `MemoryHub`; it does NOT route different keys for the same agent in production. **Pain-intensity RMW needs an explicit lock**, not the GIL: `current = get(); if intensity > current: set` is two bytecodes in CPython 3.11+ (specialised arithmetic broke the "single bytecode" assumption that the older inline-cache codepath relied on). Write a `threading.Lock` and acquire it for the read-modify-write, even if there are no production producers today (future-proofing — the bus path bypasses this stash, but the API is exposed). The corresponding `record_outcome(agent_id=...)` invariant in `runtime/tool_dispatch.py` mirrors the same shape: required keyword-only, validated non-empty, tagged onto every `nac.observe(context={"agent_id": agent_id, ...})` so per-agent attribution is filterable from the persisted `event_context`. Test discipline: when two agents share ONE NAc instance (vs two separate NAc instances per the production AgentFactory pattern), the per-agent isolation must STILL be provable via `event_context["agent_id"]` — otherwise the headline "non-overlapping signatures" claim is structurally guaranteed by separate NAc objects, not by the agent_id tag itself. See `tests/integration/test_multi_agent_attribution.py::TestSharedNacIsolation`. Reference: `docs/plans/archive/v1_refinement.md` Section 4 P4. Regression guard: [tests/integration/test_multi_agent_attribution.py](tests/integration/test_multi_agent_attribution.py) (TestSharedNacIsolation) + [src/maxim/runtime/bio_integration.py](src/maxim/runtime/bio_integration.py) (`_check_agent_id` validator rejects empty `agent_id` at every entry point).
