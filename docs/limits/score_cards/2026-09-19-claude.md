## Why each grade was earned

### Research integrity — B+

- **Every verdict reproduces from the committed data.** Agent A re-ran each pure analysis at the
  tag: Exp 60 EARNED; Exp 61 EARNED (12/12 v 0/24, 0/12, 0/24, p 7.99e-10, all six gates); R3
  amended COMPLETE, identical to `r3_report_amended.json`; R3 frozen INCOMPLETE with the same
  cause; Exp 56 and its re-baseline PASS. One drift: the committed `r3_report.json` carries an
  older field name the tag's code no longer emits.
- **1.3 provenance is clean by hand.** Exp 61 at one hash, two minutes after its freeze; R3 cal and
  bench each at one hash with the prereg on main first; Exp 60's verdict run followed five
  disclosed post-data instrument fixes, each with a regression guard.
- **Deciding gap — the enforcement does not reach 1.3.** `scripts/lint_prereg_precedes_data.py`
  runs in CI and reports clean over 33 governed experiments, but it reads only
  `protocols/*preregistration*.md`. Exp 60, Exp 61 and R3 are `docs/experiments/*_prereg.md`, so the
  release's headline results are self-attested on ordering, not enforced.
- **Post-data changes are handled in the open**: R3's two amendments with a release-day erratum and
  both reports committed; Exp 56's duplicate row disclosed and left in the file; older lost data,
  dirty-tree records and a retracted sentence disclosed on their ledger rows.
- **Small n, no independent replication.** Exp 60 is 5 v 5 seeds in one pool; the Exp 56
  re-baseline is a same-seed reproduction.
- **To reach A−:** extend the prereg-before-data lint to the `*_prereg.md` preregs and require the
  dirty-tree gate in the survival harnesses.

### Ambition and originality — B+

- **Real and wired:** substrate-primary action selection with no LLM in the loop; the fear
  subscriber auto-wired in the canonical PainBus builder; learned wants and fears moving between
  independent agents through signed bundles with bounds and a discount; a live world instrument
  whose R3 arms came out in the predicted order.
- **Narrow in what earned:** one binary cue (`is_in_water`), one action, one pool. Dark = danger is
  blocked at the instrument, eat-when-hungry is prior-driven, cross-pool generalization and delayed
  credit are untested, scaling is PARTIAL.
- **To reach A−:** an earned result on a multi-step or delayed-credit task, or in an unseen
  situation.

### Documentation honesty — B+

- **The 1.2.1 correction does not reach 1.2.1 readers:** the 1.2.1 CHANGELOG entry,

- **Enforced and passing:** version sync, link resolution, EARNED-row data citations.
- **To reach A−:** the README rewritten to the shipped positioning, the 1.2.1 surfaces pointed at

### Runtime correctness — C+

- **The core paths hold:** fast suite exit 0 (10,867 passed, 39 skipped, ~10 min);
  `test_memory_hub.py` 25/25; create → capture → shutdown → load restores memory with
  `_format_version` on every file; a corrupt file raises `MemoryCorruptionError`; four FIXED bug rows
  (D17, D42, D82, D55) each have the fix, a non-test caller and a test.
- **A documented public method silently lies:** `AgentInstance.export_memories()` reads
  `self.hippocampus.memories`, which `Hippocampus` does not have, and an `except Exception` turns the
  error into 0 (`src/maxim/runtime/agent_factory.py`). The example in `docs/user/python-api.md`
  prints "0 memories" beside `len(hippocampus) == 1`; both tests are vacuous; the swallow lint cannot
  see it (the handler assigns rather than passes); `AgentPool.export_all_memories` propagates the
  wrong count.
- **A docstring example crashes:** `create.agent`'s `capture(perception="dark cave ahead")` raises
  `AttributeError`; `capture` does not validate its argument.
- **The silent-failure surface is large:** 430 bare pass/continue handlers (the ratchet's count),
  1,788 `except Exception` sites.
- **Composition still unwired:** `make_pairing_announcer` and `make_device_speak_sink` have zero
  non-test callers (disclosed in the CHANGELOG).
- **Lesser:** `maxim.diagnose()` reports all passed while `maxim doctor --json` exits 1 on a probe
  `diagnose()` never runs; the Minecraft client accepts NaN, which the axis clamp turns into the top
  of the range (the bridge likely cannot send NaN; not run end to end); a fast-suite test leaves a
  spinner thread printing after the summary.
- **To reach B−:** fix `export_memories` with a test that asserts the count, validate `capture`'s
  argument, make `diagnose()` and `doctor` agree, and bound the handler-assigns-a-default shape.

- **The offset is real and enforced:** CI runs the orphan-module (0), atomic-io (12), swallow,

  two-process stable-hash test, the urllib grep, the raw-motion grep — a text regex that aliasing

- **To reach C+:** one god function measurably shrunk with the ratchet tightened, and the length
  ratchet extended to every function over 300 lines.

### Test quantity — A−

- **10,973 collected** (unit 9,998 / integration 368 / substrate 367 / behavioral 173; `slow` 42,
  `requires_model_cache` 21); 181k test lines against 226k src (≈ 0.80); ~134 survival-world tests,
  270 hive, 143 NAc, 364+ console.
- **Why not A:** the survival harness (~9.6k lines under `scripts/`) is thinly covered for its size,

### Test/CI truthfulness — C+

- **The signed-bundle and console paths never run in CI.** No lane installs fastapi or
  cryptography. At the tag's main run, 13 console test modules and every bundle-signing, hive-pull
  and Oasis-exchange end-to-end test were skipped — the paths behind 1.2.1 and behind the
  "shipped signed-bundle path" of Exp 61's headline. (The experiment ran that path live, with
  committed data; CI does not.) The model-cache lane's skip allow-list ratifies the console gap
  rather than closing it.
- **A nightly lane red for 16 nights:** model-cache failed every night Sep 4–19 (25 of the last 30
  runs) on console modules missing from its allow-list; 1.3.0 shipped through it because nothing in
  the release procedure reads nightly results.
- **The slow lane is green but mostly vacuous:** 12 of 54 tests ran last night, 42 skipped
  (including 24 substrate sweeps lacking sentence-transformers); its only check is executed > 0.
- **Required checks are thin and bypassable:** branch protection requires `unit-tests` and `lint`
  only, `enforce_admins` off, zero required reviews; the ruleset grants an always-bypass admin role;
  `release-build` is not required although CLAUDE.md says it is; `pr_merge_readiness.py` is manual.
- **Positives:** the PR gate runs exactly the documented commands plus ~20 invariant lints with
  positive controls; no live xfails; the R3 offline campaign's move to `slow` is justified in the
  commit and the test and passes nightly; hermeticity via HOME/HF isolation and ~48 autouse env
  scrubs (no network block).
- **To reach B−:** a gating lane that installs `[console]` and the crypto extra, the model-cache
  lane green, `release-build` required, and a release step that reads the nightly lanes.

### Release governance — B+

- **1.3.0 verified end to end:** version agrees across pyproject, `__init__`, CHANGELOG and the three
  version lines; the PyPI upload date matches the CHANGELOG date in UTC; GitHub Release assets'
  sha256 equal PyPI's; the PyPI sdist is byte-identical to the tag (520/520 src files); `v1.3.0` is
  signed (`git verify-tag` good), as are v1.1.0 onward; the notes use absolute links.
- **Enforced:** `audit_release_tags.py --check-releases` clean (14 historical versions grandfathered
  by an explicit list with reasons; 1.1.0rc1 onward clean); `lint_version_sync.py`; "main ahead of
  PyPI" by the two `[Unreleased]` lints.
- **By hand:** the UTC date, tag signing, "the tag is the published commit", the structure-or-time
  rule for gating results (the guide calls clauses (a) and (b) mechanically checkable; nothing checks
  them), the upload itself; the release audit runs only after merge and nightly, not on the release PR.
- **To reach A−:** mechanize the structure-or-time check and the tag-is-published-commit check, and
  run the release audit on the release PR.

**The two cards agree on the shape and differ on the level.** Both call the release unusually
disciplined for its kind, both name the reporting layer as weaker than the engineering underneath,
and both single out release governance as the cleanest axis. Codex's overall read is B+.

**Most of the gap tracks what each assessor could EXECUTE, not a disagreement about facts.** Codex's
container had no `pytest` — it says so plainly in two axis sections and again in its verification
notes, and declines to claim a suite pass. It verified what it could run (`lint_version_sync.py`,
`audit_release_tags.py --check-releases`, the installed version) and graded the rest from the
artifacts. This card's agents ran the fast suite, exercised the public API, collected the tests,
measured function lengths and the repo-wide mypy error count, and read the CI run history. The
rubric both cards used credits only what is enforced or demonstrated, so execution mostly moves a
grade DOWN — it is where the defects live:

- **Test/CI truthfulness (C+ vs B+)** — the widest gap, and the clearest case. This card's finding
  is that no CI lane installs fastapi or cryptography, so the console and signed-bundle tests are
  skipped everywhere, and that the nightly model-cache lane has been red for 16 nights. Both facts
  come from reading run HISTORY and the skip lists, not the workflow files, which read honest.
- **Runtime correctness (C+ vs B−)** — this card's deciding defects (`export_memories()` always
  reporting 0 behind a swallowed error; a crashing docstring example) were found by running the
  documented examples.
- **Maintainability (C vs B)** — measured spans (three functions of 1.7k–3.5k lines, 53 over 200,
  mypy 1,050 errors over the full tree) against a read of the structure and the lint estate.
- **Test quantity (A− vs B+)** — the one axis where execution moved a grade UP: 10,973 tests
  collected, test/src ≈ 0.80. Codex, unable to collect, graded the visible surface.
- **Research integrity (B+ vs A−)** — not an execution gap but a reading: this card's agent found
  that `lint_prereg_precedes_data.py` governs only `protocols/*preregistration*.md`, so none of
  1.3.0's own three experiments are covered by it. Codex credited the pre-registration discipline as
  written. Both are true; the rubric's "enforced, not documented" rule is what separates them.

**What to change next time, as a process note rather than a grade note:** give both assessors the
same evidence access — a `pytest`-capable environment and the ability to read CI run history — or
split the axes so each grades what it can execute. A card that cannot run the suite is still worth
having (it reads the artifacts a reader will read), but the two cards are then measuring different
things, and the spread between them says more about the environments than about the repo.

**Where they agree, treat it as settled:** the release chain is real and verified end to end; the
experiments' process discipline is the project's strongest feature; the reporting layer needs the
most work. This card's "to reach" conditions stand unchanged.
